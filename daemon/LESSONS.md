## <a id="1"></a>1. Broken cargo/rustc proxies — `rustup default stable` won't fix them; repoint the shims

**Date:** 2026-06-07.
**Source slice:** 0.4 (`OQ-DATA-SPIKE-3` env-finding; cleared under ③).

During Phase-0 the daemon-track build was blocked: `~/.cargo/bin/{cargo,rustc}` (and 11 other proxies, 13 total) were **broken dangling symlinks** pointing at a non-existent `/Users/nozzins` path — the artifact of a moved home directory. The real stable toolchain (1.93.0) was intact at `~/.rustup/toolchains/stable-aarch64-apple-darwin/bin`.

The non-obvious part: **`rustup default stable` did NOT fix it.** `rustup` only (re)creates *missing* proxies; it leaves *existing-but-broken* symlinks untouched. The obvious first move silently no-ops. The working fix was to repoint every broken proxy at the local `rustup` binary directly — `ln -sf rustup ~/.cargo/bin/<proxy>` for each of the 13 — after which the plain shims resolve (no PATH workaround needed). Verify with `cargo --version && rustc --version` (expect 1.93.0), `cargo clippy`, and a real `cargo build`.

Edge cases still open: if the home dir moves again the same breakage recurs; a `rustup self uninstall` + reinstall would also fix it but is heavier. Prefer the targeted shim-repoint.

**Rule:** When `~/.cargo/bin` shims are *broken* (dangling symlinks, e.g. after a home-dir move), `rustup default stable` does **not** repair them (rustup only recreates *missing* proxies) — repoint each broken proxy to the local `rustup` binary (`ln -sf rustup ~/.cargo/bin/<proxy>`), then verify with the plain shims.

## <a id="2"></a>2. The wire value is the contract; the SoT propagation pattern is §5.0 — follow it for every contract addition

**Date:** 2026-06-07.
**Source slice:** 0.5 (shared contract freeze, `OQ-DATA-SPIKE-5`).

The 0.5 freeze settled two conventions every future contract surface (event-type registry, GatewayPort schema, action-type catalog, any new enum/ID) must follow.

**(a) The serialized wire/`TEXT` value is the contract — not the in-language identifier.** Enums serialize to exact snake_case strings via `#[serde(rename_all = "snake_case")]`; each language uses its idiomatic identifier (Rust `PascalCase` variants, TS string-literal unions, Python `Enum`) but the *string on the wire / in the `TEXT status` column* is what's frozen. A round-trip test (`test_every_state_machine_value_present_and_serializes`) pins this — never assume the identifier and the wire value match. Closed-enum / reject-unknown holds end-to-end (serde closed enums → JSON-Schema `enum` → `z.enum` → Pydantic): unknown values are rejected at every boundary, which is the fail-closed posture (§15), not optional.

**(b) The source-of-truth propagation is fixed by `ARCHITECTURE.md §5.0` (Option A):** Rust `shared` crate = native authority (newtypes for IDs, serde-closed enums) → `schemars` emits a **first-class, versioned, diff-gated** JSON Schema artifact (`shared/contracts/schema/`) → TS Zod + Python Pydantic are **generated** from that artifact → a self-contained 3-way value-set equality harness proves they agree. Do **not** hand-author a consumer's types or invert the authority (an external IDL/codegen-into-the-trust-core was rejected — it generates bare types in the safety-critical module and fights the newtype posture). Every new contract addition extends the Rust authority and regenerates the artifact; the diff-gate catches drift.

**Rule:** Freeze the *wire value* (snake_case `TEXT`), not the identifier — pin it with a round-trip test; and author every contract in Rust (`shared/`) per §5.0, regenerating the published schema + consumers (never hand-write a consumer or invert the authority).

## <a id="3"></a>3. Single-write-actor — one writable `Connection`; everything else read-only WAL; canonical `seq` in one `BEGIN IMMEDIATE` txn

**Date:** 2026-06-07.
**Source slice:** 1.1 L2 (event store).

The §15 single-mutator invariant has a concrete enforced shape in the daemon: **exactly one writable rusqlite `Connection`** (owned by the write-actor); **every other access opens a read-only WAL connection** (`Connection::open_with_flags(..., SQLITE_OPEN_READ_ONLY)` / `open_read_only`). A read-path that can't even *construct* a writable handle can't violate single-mutator by construction — enforce it at the type/connection level, not by convention.

The canonical `seq` (the total event order, §7.1) must be assigned **atomically**: the `SELECT max(seq)+1` and the `INSERT` go in **one `BEGIN IMMEDIATE` transaction**, not two statements. `BEGIN IMMEDIATE` takes the write lock up front, so two concurrent appends can't read the same max and produce a gap/duplicate. A borrow-checker-only "one writer" guarantee is **not** enough — the *transaction boundary* is what makes the ordering atomic (1.1 L2 security-reviewer high finding).

Pair this with an **injectable `Clock` + `IdGen`** (constructor-injected; fakes in tests) so the event log — `seq`, `event_id` (ULID), `recorded_at` — replays **byte-identically** in the golden-log test. Determinism-for-testability is a daemon-wide seam (root `CLAUDE.md` "Determinism-for-testability"), not a per-slice afterthought.

**Rule:** One writable `Connection` (the write-actor); all other access is read-only WAL (`open_read_only`). Assign the canonical `seq` via `SELECT max+1` + `INSERT` inside one `BEGIN IMMEDIATE` txn (atomic order, not borrow-checker-only). Inject `Clock`+`IdGen` so the log replays deterministically.

## <a id="4"></a>4. Projections fold in-band in the event-commit txn; savepoint-isolated per-projector; offsets never ahead of rows; recovery = catch-up + rebuild

**Date:** 2026-06-07.
**Source slice:** 1.2 (projection engine, L1–L3 — `c8c6c72`/`a1dc482`/`e66c659`).

Projections are applied **in-band, inside the same `BEGIN IMMEDIATE` event-commit txn** as the event INSERT (`§7` "within the one event-commit transaction"; DATA_MODEL `§2.4`), *after* the §15 redaction gate — so a projector only ever sees the **already-redacted** payload, and a reader never sees an event whose (healthy) projections haven't applied. Each projector runs under a **uniquely-named SAVEPOINT**: a projector **logic error** rolls back *that projector's* rows + offset and marks `projection_offsets.state='degraded'` (skip-and-continue), while a **Db error** (or the gate) aborts the whole append closed (§15). `mark_degraded` is written *outside* the savepoint but *inside* the outer txn — so it shares the event's commit/rollback fate (atomic either way). Offsets advance in the same txn — **never ahead of the rows they represent** (crash-safe).

Recovery has two paths, both built on the strict `seq > last_seq` boundary: **catch-up replay** (wired into `open`, runs every start) folds pending events per projector — and is a **strict no-op on an already-current log** (the `>` boundary, not `>=`, guards non-idempotent counters against double-counting on reopen; pin it with a "catch-up-noop-when-current" test). **Full rebuild** truncates the derived tables (a compile-time-`const` list that **excludes `events`**) + replays all — **byte-equivalent to the incremental fold**, and raw `events` are never mutated (§7.2 "projection corruption must not corrupt raw events"). A degraded projector advances past the bad event on later successes (sticky `last_seq`), never stranded. In-band apply and replay share one `apply_one`, so the degrade semantics agree by construction. Status columns **bind the frozen §5.1 `shared/` enums** (reject-unknown), never bare strings. Guard `advance_offset`/`mark_degraded` with a rows-affected check (`expect_one_row`) — a missing offset row must not silently no-op (it would re-fold every reopen). **Open caveat:** `catch_up_replay` currently reconstructs via the *strict* read path → one corrupt event row aborts `open` (daemon-won't-start); the §17-degradable-replay fix is task 1.6 (decide skip-vs-refuse semantics + audit-integrity).

**Rule:** Fold projections in-band in the event-commit txn (after the redaction gate), each under its own SAVEPOINT (logic error → degrade+skip that projector; Db error → fail the append closed); advance offsets in the same txn (never ahead of rows); recover via catch-up replay (strict `seq>last_seq`, no-op on current) + full rebuild (truncate a const derived-table list, replay-all, byte-equivalent, raw events untouched); bind status columns to the frozen §5.1 enums.

## <a id="5"></a>5. External side-effects go through the transactional outbox: written in the event-commit txn; §15 sync-sink; at-least-once with reset-on-open

**Date:** 2026-06-08.
**Source slice:** 1.3 (transactional outbox, L1–L2 — `343cc09`/`707845a`).

Every external side-effect (Brain/GitHub/Linear/notifier/JSONL mirror) goes through the **transactional outbox**, never a direct call. Outbox rows are written **in the same event-commit txn** as the event + projections (the transactional-outbox pattern: a fact is **recorded-iff its delivery-intents are**, and **delivered-iff recorded**) — atomic with everything else; a txn abort (e.g. the redaction gate) leaves 0 events **and** 0 outbox rows. The outbox is the **§15 *sync* sink** (root rule #3 "same redactor gates persist+embed+**sync**"): the per-destination payload derives **only from the already-redacted stored event**, never re-fetched raw, and per-destination filtering only *removes* fields (e.g. Brain = envelope minus restricted/secret) — it can never re-introduce a secret. Rebuild/replay must **never re-emit outbox rows** (outbox ∉ the rebuild table list) — a read-model reconstruction must not re-deliver historical events to the outside world.

Delivery is **at-least-once** with a deterministic drainer (`drain_once(clock, dest)` — the Tokio-loop unit; the loop spawn itself is 1.6-bootstrap-wired): claim `in_flight` **committed before** `deliver` (the no-loss window), transition `delivered` / `failed`+`backoff(retry_count)` / `dead` (terminal, or retryable past a bounded `MAX_RETRIES` — bounded dead-letter, never an unbounded loop). Crash recovery = **`reset_in_flight` (in_flight→pending) wired into `open`** (single-instance-safe via the pidlock); consumers must be **idempotent** (dedup). The due-comparison `next_attempt_at <= now` is a **lexical string compare** — only sound because the `Clock` RFC3339 contract is **UTC `Z`-suffixed and format-consistent** (verify the time source emits `Z`; treat it as a Clock contract). Use a separate `IdGen` counter for `out_` ids so event-id/golden-log determinism is unchanged.

**Rule:** Route all external side-effects through the outbox: write rows in the event-commit txn (recorded-iff-intended); treat it as the §15 sync sink (payload from the already-redacted event, filter-only; rebuild never re-emits); deliver at-least-once via a deterministic `drain_once` (in_flight claim-before-deliver, reset-on-open recovery, backoff + retryable/terminal + bounded dead-letter, idempotent consumers); keep timestamps UTC-`Z` for the lexical due-compare.

## <a id="6"></a>6. Cross-restart locks — a persisted monotonic fencing high-water mark per `(resource_id, lease_kind)`; authority is a LIVE lease; single-instance via a std advisory file lock

**Date:** 2026-06-08.
**Source slice:** 1.4 (lease locks + fencing + pidlock + reaper, L1–L3 — `b3f7612`/`442149a`/`0347ac6`).

Cross-restart resource locks (ADR-008) are a SQLite `leases` row per `(resource_id, lease_kind)` carrying a **monotonic fencing token** that is a **persisted high-water mark** — minted `+1` on each acquire/reclaim and **never lowered**: `release` and the reaper NULL only the holder fields (`owner_id`/`acquired_at`/`heartbeat_at`/`expires_at`) and **keep** `fencing_token`. Because the high-water mark lives on disk in the row (not an in-memory counter, not `MAX()` over deletable rows), monotonicity **survives daemon restart** — the test pins a held+expired lease at token N → drop+reopen → next acquire mints N+1 and the pre-restart token N fails validation. Mint the token under `BEGIN IMMEDIATE` (the read-current-then-write must be one txn — LESSON §3 — or two racing acquires read the same max and collide); `renew`/`release`/`validate` are single atomic statements. `locks/` writes through the **same single writable `Connection`** the event store owns (EventStore exposes thin delegating `acquire_lease`/`renew_lease`/`release_lease`/`validate_lease_held`/`reap_leases` methods) — never a second writer (Forbidden #3).

**Authority is a LIVE lease, not a merely-unsuperseded token (Option B, human-ratified — safety rule #6).** The fencing oracle the Phase-2 gateway calls is `validate_held(resource_id, lease_kind, owner, token, now) = owner-match AND token == fencing_token AND expires_at > now`. "Stale" = **NOT a live lease — expired OR superseded** — §17 (line 387) leaves the word undefined, so the team pinned it: an **expired holder is rejected even if no one has superseded it** (the zombie-holder window), not only when a higher token was minted. The textbook supersession-only check (`token == latest`) was rejected because §17's daemon-crash recovery (line 384) re-derives an old `executing` action via the same "lease check" — authority must track **liveness**, not just supersession. Consequence flagged to Phase 2 (task 2.4): the gateway must **heartbeat/renew (or re-acquire)** a long-running action so it isn't fenced by its **own** lease expiry (a self-fence → false `fencing_conflict`).

Single-instance (the pidlock) is a **std advisory exclusive file lock** (`std::fs::File::try_lock`, stable since Rust 1.89 — toolchain is 1.93, so **no dependency**) on a lock file. The OS holds the lock against the open file descriptor → it is **auto-released on process death (including crash)** and **immune to PID reuse**: the OS-fd lock is the sole oracle. Never use a `kill(pid, 0)` liveness check — a reused PID makes it falsely conclude the old daemon is alive (false-positive block), and it can't detect a crashed holder. The PID written into the lock file is **diagnostic-only** (guarded on `set_len` success so a failed truncate can't leave misleading bytes). Fail-closed: `TryLockError::WouldBlock` → `AlreadyHeld`; `TryLockError::Error(io)` → a typed IO error — **never "acquired."**

The reaper's deterministic unit is `reap_once(now)` — it frees every lease past `expires_at` (`expires_at <= now` is the **exact complement** of `validate_held`'s `> now`, so a live lease can never be reaped) and returns the reclaimed set; the Tokio interval **spawn** is 1.6-bootstrap-wired (joins the outbox drainer spawn, §12). The whole `Lease` model is **daemon-internal** — no `proj_lease`, no `lease_` among the 22 frozen IDs, not one of the 10 §5.1 status machines, and the UI/Brain don't read the `leases` table → **no `shared/` surface, no CONTRACT_VERSION bump** (the 1.3 outbox precedent).

**Rule:** Cross-restart locks = a `leases` row per `(resource_id, lease_kind)` with a **persisted monotonic fencing high-water mark** (minted +1 on acquire/reclaim under `BEGIN IMMEDIATE`; release/reap keep it; survives restart); **authority is a LIVE lease** — `validate_held` = owner + token-match + `expires_at > now`, so "stale" = expired OR superseded (safety rule #6; the gateway must heartbeat long actions); single-instance via a **std advisory file lock** (OS-fd-held, auto-released on death, immune to PID reuse — never `kill(pid,0)`); the whole model is daemon-internal (no `shared/` surface, no CONTRACT_VERSION bump).

## <a id="7"></a>7. The UDS GatewayPort transport — length-prefix framing + getpeereid-first peer-auth + two version axes + `ServerFrame` frame-mux; ship the mechanism, wire the runtime at the bootstrap

**Date:** 2026-06-08.
**Source slice:** 1.5 (UDS GatewayPort transport, L1–L4 — `ae27f1d`/`fb941e8`/`c1c54e5`/L4).

The out-of-daemon GatewayPort transport (§6.4) is a UDS server with **4-byte big-endian length-prefix + JSON-body** framing, bounded by `MAX_FRAME_SIZE` (8 MiB) — an oversized frame is rejected **from the length prefix alone, before any body allocation** (anti-DoS). Peer-auth (safety rule #7 / ADR-004) is **`getpeereid()` called FIRST in the per-connection handler** — a peer whose uid ≠ the daemon-uid is dropped + disconnected before any frame is read; **`getpeereid`, NOT `SO_PEERCRED`** (Linux-only). Isolate the FFI in one `peer_uid(fd)` fn + **fail-closed** (a getpeereid error is never "authorized"; no uid-width cast that could silently truncate). Test the peer-auth **enforcement** path, not just the predicate — give the per-connection handler `peer_uid` as a **parameter** so a foreign-uid → disconnect is pinned deterministically (you can't spawn a foreign-uid peer in a unit test).

There are **two independent version axes** — don't conflate them: **`CONTRACT_VERSION`** is the §5.0 schema/codegen artifact version (the IPC method/error/frame schemas authored in `shared/` → schemars → the ui's generated validators; bumped per additive surface, gated by the byte-diff + 3-way verify); **`protocol_version`** is the §6.4 wire-handshake compatibility check (`HelloFrame`→`HelloAck`|`VersionSkewError`; `SUPPORTED_PROTOCOL_RANGE = {min:1,max:1}`, **daemon-authored** — the ui pins provisionally + reconciles to the daemon's range). Handshake-FIRST (after peer-auth): no method is served before a successful handshake; a version-skew or malformed/non-Hello first frame fails closed → structured error + disconnect.

When the architecture's LOCKED error-code set is found incomplete at implementation time, that's a **Finding → escalate the contract correction** (here: §6.4's 6-code set had no code for a bad-first-frame / handshake-required / malformed / bad-params violation; lead-ratified Option B added **`protocol_error`** — `unknown_method` is reserved for a genuine unknown method NAME). Frame-type multiplexing (§6.4, so the Terminal Channel can share the socket) is an **internally-tagged `ServerFrame`** (`{frame_type: rpc_response | subscription_push}`, Terminal reserved) — a JSON discriminant over the **unchanged** codec, NOT a binary type-prefix (which would retrofit the committed codec; the raw-byte Terminal encoding is a **measured Phase-3 call**). The dispatch **error split**: an **infra** error (a failed frame read) disconnects; a **client** `WireError` (`protocol_error`/`unknown_method`/bad-params) is returned and the connection continues. Read methods (`get_projection`/`subscribe`) read **read-only WAL** (`open_read_only`; single-writer preserved — LESSON §3); the projection-name→`proj_*` map is a **closed-enum const** (never client input → no SQL injection); an unfed projection returns its **empty table**, not an error.

The whole server's production wiring lives at the **1.6 bootstrap** (the runtime spawn): `bind()` + the accept-loop, the live `subscribe` delta-source (`EventStore::append`→a broadcast→the subscriber push, via a `try_clone` read/write split), the **platform cfg-guard** (getpeereid is macOS/BSD-only — a Linux build won't link), and an accept-loop **concurrency cap**. 1.5 ships the **mechanisms + the cross-language contract** (testable over a temp socket + with fed deltas); the runtime sources wire at 1.6 — the same "ship the deterministic unit, wire the production source at the runtime" pattern as the 1.3 outbox drainer + the 1.4 reaper. Reachability is stated honestly per layer (pub primitive, consumer-wired later) — never claimed live.

**Rule:** The UDS GatewayPort transport (§6.4): 4-byte-BE-length-prefix + JSON framing (oversized rejected pre-alloc; `MAX_FRAME_SIZE` 8 MiB); **`getpeereid()` peer-auth FIRST** (reject uid≠daemon-uid; NOT `SO_PEERCRED`; isolated unsafe + fail-closed; test the *enforcement* path via an injectable `peer_uid`); handshake-first; **two version axes** (`CONTRACT_VERSION` schema/codegen vs `protocol_version` wire-skew, `{1,1}` daemon-authored); a LOCKED-error-set gap → escalate the contract correction (`protocol_error`); frame-mux via an internally-tagged `ServerFrame` over the unchanged codec (Terminal encoding = a Phase-3 measured call); read-only-WAL reads + a closed-enum table map (no injection); ship the mechanism + contract now, wire the runtime source (bind/accept/subscribe-broadcast) at the 1.6 bootstrap.

## <a id="8"></a>8. Cold-start bootstrap — strict ordering (pidlock-first, before any DB write) + determinism-for-testability on the FS failure path

**Date:** 2026-06-08.
**Source slice:** 1.6a L1+L2 (cold-start bootstrap + migration typed errors — `48b7a2c`/`f1de088`).

Cold-start (§16) **composes** already-shipped mechanisms in a binding order: `create_dir_all` (the app-support dir prereq) → **`PidLock::acquire` (the FIRST refusing gate)** → `EventStore::open` (which itself runs pragmas → version-floor → migrate-with-backup/rollback → catch-up-replay → outbox crash-recovery). The pidlock MUST come before any DB write: two instances that both reached `migrations::run` concurrently would corrupt the event-log spine (forbidden #3) — single-instance is a *precondition* of the single-writer, not a parallel concern (the security-reviewer pins this ordering). `EventStore::open` + `migrations.rs` **already** enforce the §16 DB lifecycle (backup on `from≥1`, restore-on-failure, `refuses_db_newer_than_supported` floor) from 1.1 — bootstrap composes them, it does **not** re-implement; the genuinely-new bootstrap work is the *ordering* + the version-info composition + the (user-gated) registration layer.

The §16 version-compat "matrix" has exactly one *enforcing* floor at bootstrap — the DB `user_version` check (`refuses_db_newer_than_supported` → refuse-safe on a DB newer than the binary). The other rows are NOT enforced here: `app_version`↔protocol-range is enforced at the 1.5 wire handshake; the agent-CLI/SDK tuple + the sidecar-MCP `initialize` check are §9.1/§13.1, deferred. So `DaemonVersionInfo` *reports* the tuple (`app_version=CARGO_PKG_VERSION`, protocol_range, db_user_version, contract_version) for diagnostics/handshake, and only the DB floor *refuses*.

Determinism-for-testability on an FS failure path: a symmetric backup/restore copy path can't be broken mid-flow deterministically (you'd need a forced disk fault). Instead **extract the decision into a pure classifier** — `on_migration_failure(restore_result, from, migration_err)` — and unit-test the *classification*: a clean rollback → a "rolled back to vN"-renderable `Migration` error that **preserves the original migration-error context** (don't drop it); a rollback-that-also-failed → a **distinct typed `RestoreFailed{from, ..}`**, never the swallowed `let _ = restore_db(..)`. The pure-helper + inline-unit-test pattern (the `outbox.rs` precedent) covers the safety-relevant decision without an un-deterministic disk fault. Typed-result discipline: kill `-1` sentinels in version-compat code (`user_version() -> Result<u32>`; an out-of-`u32` value maps to a typed `Migration` error, never `Reconstruct`).

**Rule:** Cold-start = `create_dir_all` → **`PidLock` (first refusing gate, strictly before any DB write — forbidden #3)** → `EventStore::open` (compose the already-shipped migrate/backup-rollback/floor/replay — don't re-implement); the §16 version "matrix" *enforces* only the DB `user_version` floor at bootstrap (the rest are report-only / handshake / deferred); pin an FS failure path by extracting a **pure classifier** (`on_migration_failure`) + inline-unit-testing the decision (preserve the original error context; emit a distinct typed `RestoreFailed`; no `-1` sentinels) rather than forcing a disk fault.

## <a id="9"></a>9. The daemon runtime — single write-actor (dedicated blocking thread + mpsc), publish-after-commit broadcast, readers never block the writer; unlink-before-bind

**Date:** 2026-06-08.
**Source slice:** 1.6b (daemon runtime — write-actor + `main.rs` + drainer/reaper + UDS accept-loop + broadcast — `26898a8`/`9448035`/`8d06ed7`/`f9c31b1`/`39f756e`).

The locked single-write-actor (LESSON §3) is realized at the runtime as a **dedicated OS thread** that owns the writable `EventStore`, fed by an **mpsc command channel** — rusqlite is blocking, so the writer must NOT be an async task (it would block the Tokio runtime). A `WriteHandle` (Clone+Send) exposes async methods (`append`/`drain_once`/`reap_leases`/`subscribe`) that send a command + await a oneshot reply. **Reads never touch the actor** — every read path opens `open_read_only` (forbidden #3). The outbox drainer + lease reaper are async interval tasks that send commands to the writer (a **bounded** drain pass so a backlog can't starve the writer; `MissedTickBehavior::Delay` so a slow pass doesn't burst-catch-up). Graceful shutdown closes the channel + joins the thread (a `WriteActor` `Drop` + a `biased` shutdown-priority select).

The **live subscribe delta source** is a `tokio::sync::broadcast` sender held by the write-actor that publishes the resulting `ProjectionDelta`(s) **after** the append commits (never an uncommitted/rolled-back delta). The critical forbidden-#3 corollary: **a subscriber must NEVER back-pressure the writer** — a lagging subscriber's `broadcast::error::Lagged` is detected + the subscriber resyncs (re-`get_projection`), it does not stall the sender (so no resync wire frame + no CONTRACT bump). (The socket subscribe-**SERVE** push — threading the broadcast `Sender` into `serve_connection`/the accept-loop + the post-ack streaming path — is the carved **1.6d** follow-up; the SOURCE is live here.)

UDS bind = **unlink-before-bind** (reclaim a stale socket file so `bind` doesn't `EADDRINUSE`) — safe because the 1.4 pidlock guarantees single-instance, so any existing socket is stale. The accept-loop hands each connection to `serve_connection` on a `spawn_blocking` task (the read path is sync rusqlite), under a **semaphore concurrency cap** (bound live connections + 8-MiB frame buffers; the permit releases on connection close — pin both the at-cap rejection AND the permit-release). `main.rs` (`#[tokio::main]`) is the production entry: `cold_start` → start the write-actor → spawn drainer/reaper/accept-loop → block on SIGTERM/SIGINT → graceful drain. This closes the 1.3/1.4/1.5 "ship the unit, wire the runtime at 1.6" deferral chain (`/wired main.rs` reaches them all).

**Rule:** The daemon runtime = a single **write-actor** (dedicated blocking thread + mpsc + a Clone+Send `WriteHandle`; reads always `open_read_only`, never the actor — forbidden #3); the drainer/reaper are async interval tasks sending **bounded** commands (`MissedTickBehavior::Delay`); the live subscribe source is a broadcast that publishes **after commit**, and a **lagging subscriber resyncs, never back-pressures the writer** (no wire frame, no CONTRACT bump); UDS bind = **unlink-before-bind** (pidlock makes a stale socket safe to reclaim) + `spawn_blocking(serve_connection)` per connection under a semaphore cap (pin rejection AND permit-release); `main.rs` (`#[tokio::main]`) wires it all, closing the 1.3/1.4/1.5 runtime-deferral chain.

## <a id="11"></a>11. Degradable catch-up replay — quarantine + audit-integrity, the daemon never won't-start on one bad row (§17 Option C)

**Date:** 2026-06-10.
**Source slice:** 1.6c (§17 degradable replay + audit-integrity event — L1 quarantine/degrade daemon-internal; L2 `AuditIntegrityViolation` event, CONTRACT_VERSION 0.12.0→0.13.0).

The strict replay path (1.2) reconstructs every row, so **one** corrupt event row aborted `open()` → the daemon wouldn't start (no in-product recovery, `rebuild` sat behind the failing `open`). §17 Option C (user-ruled) makes the read path **degrade instead of crash**. The split is load-bearing and matches §17 as written: an **unknown `event_version`** row is a *forward-compat* situation → **DEGRADED** (mark `projection_offsets.state='degraded'`, continue; a newer binary folds it later) — **no** quarantine, **no** audit-integrity event. A **corrupt** (reconstruction-fail) **or** an **unredacted** (`redaction_status='unredacted'`, §15 defense-in-depth) row is an *integrity* event → **QUARANTINED**: recorded in a daemon-internal `quarantine` table (`seq` PK, structural reason, `detected_at`, `audit_emitted`; MIGRATION_6; outbox/leases-analogous), the raw spine left untouched, the row skipped (not folded). `replay()` is shared by `catch_up_replay` + `rebuild`, so both degrade from one change; offset semantics are unchanged from `apply_one` (a skipped row doesn't advance the offset; a later healthy row advances past it; trailing skipped rows re-read idempotently).

The "loud record" is a separate post-`open` step (replay stays append-free): the caller (`cold_start`) emits one **`AuditIntegrityViolation`{seq,reason}** System-actor event per *newly*-quarantined seq via the write-actor `append` path — like the 1.6a-L3 self-registration (LESSON §10), it passes the §15 redaction gate + projector fold and lands in `proj_audit_trail` (consumer-visible), and is NOT a Gateway Action. **Exactly-once across restart AND rebuild** needs three things together: emit only `WHERE audit_emitted=0` + set the flag after, an `idempotency_key=audit-integrity-{seq}` backstop for a crash between append and mark, and — critically — the quarantine insert is **`ON CONFLICT(seq) DO NOTHING`** (the `quarantine` table is NOT in `REBUILD_TABLES`, so a rebuild re-detects the same seqs; REPLACE would reset `audit_emitted=0` → a duplicate AIV). The persisted `reason` is a **structural descriptor** (the serde error string is discarded) so no row content reaches the audit trail (§15; the redactor on append is only the backstop). Healthy logs replay **byte-identically** to the strict path (rebuild-equivalence preserved — the degradable path must not change healthy behavior).

**Rule:** A read path that reconstructs persisted rows must **degrade, not crash**, on a bad row (§17): split *forward-compat* (unknown version → degraded-only, a newer binary folds it) from *integrity* (corrupt/unredacted → quarantine the raw row in a daemon-internal table, skip it, mark the offset degraded, **continue so the daemon starts**). Make the integrity event **loud** (a System-actor `AuditIntegrityViolation` per newly-quarantined seq, emitted post-`open` so replay stays append-free) and **exactly-once across restart AND rebuild** (`audit_emitted` + idempotency_key + `ON CONFLICT(seq) DO NOTHING`, with the quarantine table excluded from `REBUILD_TABLES`). Persist a **structural, content-free** reason (discard the serde string; the redactor is only the backstop). Pin the healthy-path with a byte-identical rebuild-equivalence test — the degradable path must never change healthy behavior.

## <a id="12"></a>12. Socket subscribe-SERVE — close-on-lag is the resync trigger; a subscribe connection is structurally single-writer

**Date:** 2026-06-10.
**Source slice:** 1.6d (socket subscribe-SERVE push — `93f70a5`; closes the ui live-subscribe path).

The broadcast subscribe-**SOURCE** (1.6b, publish-after-commit) reaches the socket here: on a `subscribe` request, `serve_connection` mints the broadcast `Receiver`, writes the ack on the main thread, then — **only if the ack succeeded** — spawns a single push thread owning a `try_clone`'d write half that streams matching `ProjectionDelta`s as `ServerFrame::subscription_push`. Minting the receiver **before** the ack is load-bearing: a broadcast only delivers to receivers live at send time, so a delta published right after the ack would be missed if you subscribed after — the receiver buffers from mint-time and the push thread drains it.

Two invariants this slice pins. **(1) Close-on-lag = the §9 resync trigger.** A pure `next_push_action(recv_result, subscribed) -> Push | Skip | Stop` classifier maps `Ok(matching)→Push`, `Ok(other)→Skip` (filter — not a gap for this subscription), `Err(Lagged)→Stop`, `Err(Closed)→Stop`. `Stop → shutdown(Shutdown::Both)` so the main read loop unblocks (EOF) → the client re-establishes (reconnect → re-subscribe → re-`get_projection`, a fresh consistent snapshot). **Lagged must NOT silently continue:** `ProjectionDelta` carries no seq/offset, so a gapped stream is undetectable by the client → its projection would silently diverge. Close-on-lag is what makes LESSON §9's "lagging subscriber resyncs, no wire frame, no CONTRACT bump" actually true — the close IS the resync trigger. Extracting the decision into a pure classifier pins it (incl. `Lagged→Stop`) deterministically, no timing flakiness (`run_push_loop_closes_connection_on_lag`: a pre-lagged cap-1/3-sent receiver → the client read-half sees EOF, never a gap). **(2) A subscribe connection is structurally single-writer.** Two concurrent writers on one socket (the ack/RPC-response writes on the main thread + the push thread) **interleave + corrupt the frame stream** (a HIGH, found + fixed + re-reviewed in-slice). Fix: subscribe is **terminal/dedicated** — main writes the ack, spawns the sole push thread only on ack-success, then the main loop is **read-only until EOF** (writes nothing); exactly one push thread per connection (bounded by the accept-loop cap). The ui must open a dedicated connection for subscribe (no multiplexing RPC + subscription on one connection — deferred with `subscription_id`). `getpeereid` stays first (rule #7; the push is post-auth/post-ack); the subscriber never back-pressures the writer (forbidden #3).

**Rule:** A push-stream over a shared socket must be **structurally single-writer** — make a subscribe connection terminal (write the ack on the main thread, spawn the *one* push thread only on ack-success, main loop read-only-until-EOF after) so the ack/RPC writes can't interleave with push frames (concurrent writers corrupt the frame stream). Mint the broadcast receiver **before** the ack (don't miss a just-after-ack delta). Drive the per-recv decision through a **pure classifier** (Push/Skip/Stop) so the policy is unit-testable without timing flakiness; **`Lagged → Stop → close the connection`** is the resync trigger (the client reconnects + re-`get_projection`) — never silently continue when the delta has no seq for the client to detect the gap. Subscriber never back-pressures the writer (forbidden #3); peer-auth stays first (rule #7).

## <a id="13"></a>13. The §15 redactor — entropy fallback + mask-in-place; quarantine-divert is the wired-but-MVP-unreached net; recall is a human gate

**Date:** 2026-06-10.
**Source slice:** 1.7 (redactor entropy fallback + quarantine-divert — L1 `c795668` + L2 `f807913`; CONTRACT_VERSION 0.13.0→0.14.0; the last Phase-1 slice). **Extended 2.0-SEC** (2026-06-11; measured recall/precision against a synthetic corpus + JSON-value detection, human-ruled Option B; engine `v2→v3`; daemon-internal, no CONTRACT_VERSION bump).

The 1.1 `PrefixRedactor` redacts-or-passes (token prefixes + PEM) and never quarantines. 1.7 raises recall (OQ-SEC-2) and adds the quarantine path. The detection now: known prefixes/PEM · **Shannon-entropy on `KEY=value`** values (≥20char/≥4.0 bits; base64/whitespace/quote-aware value span; **sub-run-scored** so a long low-entropy pad around a short secret can't dilute the average below threshold) · **bare high-entropy runs** (≥40char/≥4.5 bits — above ULID-ID length [≤31] and hex-SHA entropy [~4.0], so IDs/SHAs are spared). All three are masked **IN-PLACE** (replace the span with `[REDACTED]`), engine `prefix-entropy-v2`; the masking is a pure function of the payload (deterministic — golden-log-safe).

The key design call: **prefer mask-in-place over quarantine-divert whenever the secret span is boundable.** §15's "quarantine the event when a secret can't be safely redacted" is a *divert* — the original event is NOT persisted; a content-free `SensitiveOutputRedacted{original_event_type, reason, detector}` is recorded in its place (the gate then only ever sees Redacted/Unredacted; `RedactionStatus` stays frozen at 2). But divert is **destructive** (a false divert loses the whole event), whereas a false mask loses only the masked span — so for any *boundable* run, mask. The real `PrefixRedactor` therefore **never sets a quarantine signal** (it masks everything); the divert path is wired in `append()` + pinned by a `ForcesQuarantine` test redactor, but is **MVP-unreached** — a §15 analogue of the §17 quarantine (which only fires on real corruption). Mechanics that matter on the divert: a **namespaced** idempotency_key (`divert-{k}` — never collides with the original's key; retry-dedups), sensitivity **reclassified** to Internal (the record isn't the original's Secret), and a **fail-closed no-recurse guard** (a quarantine signal on an SOR event itself → `RedactionRequired`, never an infinite divert).

Recall has an inherent envelope: a statistical detector cannot catch JSON-`"key":"value"` short non-prefixed secrets (scoping to env-style `KEY=value` deliberately spares prefixed-ULID IDs/URLs), hex secrets at ~3.8 bits (indistinguishable from a git-SHA), or an adversarially split-and-padded secret. The §15 **fail-closed GATE invariant holds regardless** (no event persists `unredacted`; pinned by a property/fuzz test over the catchable set) — recall is about the heuristic, not the gate. Because the user made 1.7 BLOCKING + human-owned so recall can't *silently* drift, **the recall-envelope acceptance is a human gate**, not an orchestrator call; the primary secret control remains §15 rule #5 (secrets never in payloads — keychain-refs only), the redactor being defense-in-depth for accidental leaks.

**2.0-SEC measured + extended the envelope (human-ruled Option B, 2026-06-11).** A synthetic labeled corpus (correctly-shaped fakes, never real secrets — a *real*-secret corpus would itself violate rule #5; sentinel-guarded) + a pure precision/recall/FP-rate harness (`daemon/tests/redaction_recall.rs`; metric accessors are `Option<f64>` so an undefined cell is explicit not a silent 0.0/NaN; `catchable` is an **intrinsic per-sample label** — fixed at corpus-definition, never derived from redactor output — so the recall floor is non-circular and a real regression can actually fail it) turned the qualitative envelope into numbers: `prefix-entropy-v2` measured **recall_catchable 1.0 / precision 1.0 / FP-rate 0.0**, so the thresholds were **confirmed sufficient on the corpus** (not retuned — the named consts pinned with the measurement as justification). The human then ruled **Option B**: a third **JSON-`"key":"value"` value pass** (wire order **kv→json→tokens→PEM**) masking a high-entropy quoted value at the KV-confidence bar, **sub-run-scored** (a log-line's short words never trip it; whole-value entropy on prose would FP) and guarded by a **value-shape ID-allowlist** (`is_id_shape`: git-SHA / ULID / UUID by shape, not key-name — robust + avoids an unbounded maintenance surface), closing residual (a) for **≥20-char** JSON values at **zero precision cost** (FP held 0.0). Engine `v2→v3` (the recall bar moved → provenance must reflect it; free-string value → no CONTRACT bump; update every literal pin incl. the persisted-engine golden test). Composition is **additive** — a value is emitted verbatim or fully `[REDACTED]`, so a later pass never un-catches an earlier catch (no recall regression; security-reviewer-verified). **Option C (sensitivity-gated quarantine-bias) deferred** — the mask-in-place-over-divert preference above holds; a fast-follow only if real sensitive-payload traffic warrants arming the still-MVP-unreached divert. Surviving residuals are now **measured + accepted-and-owned**: (b) hex≈git-SHA (**irreducible by tuning** — can't lower the bar without masking real SHAs), (c) adversarial split-into-<20-char, (<20ch-a) sub-20-char JSON values; the corpus is a **living regression fixture** (recall-floor/FP-ceiling pinned, ratchets up only).

**Rule:** Secret redaction = high-recall prefix set + Shannon-entropy on `KEY=value` (base64-aware value span, **sub-run-scored** vs padding-dilution) + **JSON-`"key":"value"` value masking at the KV bar (sub-run-scored, value-shape ID-allowlist)** + bare-run masking, all **mask-in-place** (deterministic; engine-version-stamped). **Prefer mask-in-place over quarantine-divert** when the span is boundable (a false divert loses the whole event; a false mask loses only the span) — so the real redactor never diverts; the quarantine→`SensitiveOutputRedacted` divert is the §15 "can't-safely-bound" net, **wired + ForcesQuarantine-tested but MVP-unreached** (content-free record, namespaced dedup key, sensitivity-reclassified, fail-closed no-recurse — mirroring the 1.6c AIV). A statistical detector has an inherent recall envelope; the §15 **gate** holds regardless (pin it with a property/fuzz test), and **recall acceptance below the §15 bar is a human gate**, not a silent carry-forward. **Measure the detector against a synthetic-but-representative labeled corpus** (never commit real secrets; intrinsic per-sample `catchable` labels; `Option<f64>` metrics) and **pin recall-floor + FP-ceiling as regression consts that only ratchet up**; **extend recall via a different mechanism, not a looser threshold** (entropy can't separate a hex secret from a git-SHA — extension = JSON-value scoping + a **value-shape ID-allowlist**, sub-run-scored, at zero precision cost), bumping the engine version whenever the bar moves. ## <a id="15"></a>15. Freezing a new model surface through schemars/§5.0 — the three emission gotchas that silently break the freeze

## <a id="17"></a>17. A projector reads IMMUTABLE fields from a sibling durable-registry row, but MUST derive MUTABLE state from the EVENT — never the row's current value (rebuild-determinism)

**Rule:** A projector may read **IMMUTABLE** fields from a sibling durable-registry row (same txn — the registry tables aren't truncated on `rebuild`, so they read at FINAL value), but MUST derive every **MUTABLE** field from the **event type**, never the row's current value — else `rebuild()` is non-deterministic (stamps the final state onto every historical row).
