# /tdd brief — claude_adapter_launch_status_observe

## Feature
Implement the **Claude Code `HarnessAdapter` (part 1 — the observe path)**: `capabilities()` (the 10 Claude `HarnessCapabilities`), an **O-13-compliant `launch()`** (interactive PTY via the 3.4 `PortablePtyHost` — **`default` permission mode only, `PreToolUse` hooks + statusLine wired to the daemon, NO `-p`/SDK-drive, NO background subagents**), and **`stream_status()`** — a pure derivation of the §5.1 `Session` 17-state from Claude's **structured signals** (hook events + transcript), **never PTY-scraped (safety #9)** — plus `read_transcript()`. This is **PTY-primary** per the cat-4 ruling. The safety-critical **`MutationIntercept`→Gateway (INV-SEC-1)** path + **telemetry emission** are the next brief (043); `resume()` is minimal here (survival = Phase 4).
