# /tdd brief — claude_mutation_intercept_gateway

## Feature
The **Claude `MutationIntercept`→Gateway interception (INV-SEC-1)** — the first real harness mutation chokepoint. A Claude `PreToolUse` hook → the daemon **hook-receiver** → a `MutationIntercept{tool,params,decision_sink}` → routed through the **existing Gateway pipeline** as a **typed, risk-classified, adjudication-only `ActionRequest`** (Option A, lead-ruled) → policy/approval → an **audit-written-BEFORE-verdict** `MutationVerdict{Allow|Deny}` back to the hook (Allow→the agent proceeds; Deny→blocked; **the daemon adjudicates + audits, the agent executes**). The **load-bearing safety crux: O-13 coverage-gap compensation** — any agent mutation path the hook does NOT reliably intercept is an INV-SEC-1 bypass, so it is **denied + compensated + documented**. Telemetry emission is a separate brief (044).

**L2 — the daemon hook-receiver ingress → `MutationIntercept` (one commit; `security-reviewer`):**
- [ ] `daemon/src/harness/claude/intercept.rs` (NEW) — the **hook-receiver**: ingests the `PreToolUse` payload (`{tool_name, tool_input, session_id, permission_mode}`) the 042 launch settings route to the daemon → constructs a **`MutationIntercept{tool, params, decision_sink}`** and maps `tool_name` → its agent-mutation `action_type`. **Fail-closed:** a malformed payload, an **unmapped/unknown tool**, or `permission_mode != default` (O-13 #10 — a non-default mode means interception isn't guaranteed) → **Deny** (never construct an un-adjudicated allow).
- [ ] `ClaudeAdapter::intercept_mutation()` returns the pending `MutationIntercept` (the 042 stub → real); the ingress transport (hook-command ↔ daemon) is the Step-2.5 Q1 seam (a `GatewayPort` method vs a dedicated hook socket vs the daemon-CLI — default vote in Q's). The pure mapping (`tool_name`+`permission_mode` → `action_type`-or-Deny) is test-first.

**L3 — the `MutationIntercept`→Gateway routing + the adjudication-only verdict (one commit; INV-SEC-1 core; `security-reviewer`):**
- [ ] The intercept routes to the **existing Gateway**: build an agent-mutation `ActionRequest` (`requester_type = session_adapter`, the mapped `action_type`, `inputs` = the redacted tool params) → **`submit_action`** → `CatalogPolicy::decide` (risk-0→allow / risk-2+→require_approval / deny-rule→deny) → **adjudication-only verdict**: on `allow` (risk-0) or `approved` (the human cleared the `proj_approval_queue` item) → **`MutationVerdict::Allow`**; on `deny`/`denied`/`expired`/no-decision/timeout → **`MutationVerdict::Deny{reason}`**. The verdict returns through the `decision_sink` → the hook (allow/deny the agent's tool).
- [ ] **Audit-write-BEFORE-verdict (§15 #5, fail-closed):** an `Allow` is gated on the authoritative `ActionRequested`/`ActionApproved` event being **durably committed FIRST** (the 2.4 fail-closed-on-audit-write pattern — the verdict is the side-effect; it must never precede its audit record). An audit-write failure → **Deny** (never Allow without the record).
- [ ] **The adjudication-only outcome:** the agent-mutation `ActionRequest` reaches its verdict terminal (`approved`→Allow-verdict / `denied`→Deny-verdict) and **does NOT enter `queued`→`executing`** (no daemon executor — pinned by a test that asserts no executor runs for an `Adjudication`-class action; the INV-SEC-1 "no executor except via the pipeline" test still holds — this class has no executor *by design*).
- [ ] A `FakeHookReceiver`/synthetic-`MutationIntercept` test drives the full path (intercept → submit → policy → verdict) through `FakeHarness` + the real `submit_action` (no live Claude): risk-0 tool → Allow (auto); a risk-2 mutating tool → require_approval → (test approves) → Allow; a deny-rule tool → Deny; an audit-write-fault (the §14 fault-injection feature) → Deny (fail-closed).

**L4 — the O-13 coverage-gap compensation (one commit; THE load-bearing crux; `security-reviewer`):**
- [ ] **Deny any agent mutation path the hook does NOT reliably intercept** (the §9.1 `MUTATION_COVERAGE_MATRIX`): a tool reaching the receiver under a **non-`default` permission mode**, a **background-subagent** origin (#27203 — `Unsupported`), or any tool the matrix marks `NotGuaranteed`/`Unsupported` for Claude → **Deny** (an uncovered mutation is a bypass). `BestEffort`/`GuaranteedInDefaultMode` are allowed-to-adjudicate (the hook covers them in default mode).
- [ ] **Params-sensitive risk bump + O-13 deny-rules** in the policy path: known-dangerous patterns (e.g. a `Bash` command matching a destructive/secret-exfil/`--dangerously`-style deny-rule) → **Deny outright** (never reach approval); the bump can raise a mutating tool's effective risk (the base catalog risk is the floor). The deny-rules are a **pure, tested predicate** (no false-allow).
- [ ] The launch-side compensations are **asserted present** (cross-checking 042): `default`-mode-only + no-bg-subagents (the spec is the #10 surface). The **coverage matrix is documented + compensated** — a test enumerates each `(Claude, channel)` matrix cell and asserts the receiver's disposition (adjudicate vs deny) matches the cell's coverage (the §14 conformance assertion: "gaps documented + compensated").
- [ ] All tests pass; `/preflight` clean (fmt + clippy `-D warnings` + suite + `emit_schema` no-diff after the 0.22.0 regen).
