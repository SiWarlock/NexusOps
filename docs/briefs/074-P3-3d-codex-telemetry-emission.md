## Feature

## Acceptance criteria (what "done" means)
- [ ] The `CodexAdapter` tracks cumulative usage and `telemetry_heartbeat()` returns a **per-heartbeat DELTA** `TelemetrySample` (`tokens_in`/`tokens_out`/`cost_estimate` = current_cumulative − last_emitted_cumulative), **not** the cumulative snapshot — so the SUMming `proj_usage_ledger` doesn't over-count. `None` before the first reading. **REUSE** `claude::telemetry::telemetry_sample` (do not re-derive).
- [ ] `context_pct` is carried as the **CURRENT gauge** (pass-through), **NOT** a delta (the projector takes `context_pct_max`); `Unavailable` when `model_context_window` is absent (the existing parse.rs behavior — never a faked 0%, §11.4).
- [ ] A new cumulative reading emits **exactly one** `TelemetrySampled{sample(delta), model, execution_profile_id}` through the injected `TelemetryEventSink` (the 044 seam); the production sink-binding + the periodic pump + the live `token_count` ingress = the **live-Codex follow-on** (named deferral, the 044/P4 + 3.3c-app-server precedent).
- [ ] **🆕 Codex cost derivation (the new-vs-044 piece):** a **PURE** fn `codex_cost_estimate(tokens_in, tokens_out, model) -> f64` maps token counts → cost via a documented per-model **rate table** (`$/1M in` + `$/1M out`); `cost_estimate` rides the **DELTA** (pricing is linear → `rate × token_delta`); an **unknown/absent model → 0.0** (conservative — the sample still carries the token deltas, never a fabricated cost). Replaces `codex/parse.rs:116`.
- [ ] **🆕 Cost honesty (§11.4):** any sample carrying a **locally-derived** cost has `metric_quality` **≤ `Estimated`** — NEVER `Exact` (a local pricing estimate is not authoritative, unlike Claude's upstream-reported cost). When the model is unknown (cost 0.0) the existing context-driven quality stands; when a cost IS derived, downgrade `Exact`→`Estimated`. (The Claude-Exact vs Codex-Estimated divergence is the load-bearing honesty pin.)
- [ ] **End-to-end DELTA + UTC-`Z` pin:** append the emitted delta `TelemetrySampled` events through the **REAL write-actor** (fake Clock, UTC-`Z`) → the `proj_usage_ledger` rollup has `tokens_in`/`tokens_out`/`cost_estimate` == the cumulative total (SUM-of-deltas) and `bucket_day` == the UTC date. (Proves delta-not-cumulative AND UTC-`Z` bucketing through the real path — the 044 #7 pattern, Codex variant.)
- [ ] The `daemon/tests/codex_adapter.rs` stub-marked test updated — `telemetry_heartbeat` is no longer an always-`None` stub.
- [ ] All unit tests in `daemon/tests/codex_telemetry.rs` pass; the Codex `proj_usage_ledger` integration (`telemetry_pump.rs` or `projections.rs` — Step-2.5 Q) passes; `/preflight` clean.

## RED test outline (Step 2) — `daemon/tests/codex_telemetry.rs` (+ the integration pin)
1. **`test_codex_heartbeat_emits_deltas_not_cumulative`** — two CUMULATIVE Codex readings → the second `telemetry_heartbeat()` (after `push_usage`) returns the DELTA, not the cumulative. Asserts: delta == current − last_emitted. Why: §9.1 deltas-not-cumulative (LESSON 27; `proj_usage_ledger` SUMs).
2. **`test_codex_first_reading_full_delta_from_zero`** — the first `push_usage` emits the reading as-is (delta from 0); `telemetry_heartbeat()` is `None` pre-reading. Asserts: first delta == first cumulative; pre == None. Why: no double-count on session start, no fabricated pre-reading (§11.4).
3. **`test_codex_context_pct_is_gauge_not_delta`** — readings with `context_pct` 30%→55% emit 30 then 55 (pass-through), not a 25 delta; `model_context_window` absent → `Unavailable` (never 0%). Why: the tokens-delta-vs-context-gauge distinction (`usage.rs` `context_pct_max`).
4. **`test_codex_push_usage_emits_one_telemetry_sampled_via_sink`** — a `CollectingSink` double; one `push_usage` → exactly one `TelemetrySampled{sample(delta), model:Some, execution_profile_id}`. Asserts: sink called once; payload carries the delta + model + profile (the `usage.rs` rollup dims). Why: the 044 `TelemetryEventSink` seam (LESSON 23/27).
5. **`test_codex_cost_derivation_and_honesty`** — `cost_estimate` == `rate(model) × token_delta` (a known model); `metric_quality` is downgraded to `Estimated` whenever a cost is derived (NEVER `Exact`). Asserts: cost == the table-derived delta; quality ≤ Estimated on a derived cost. Why: §11.4 honesty (a local estimate is not authoritative; the Claude-Exact vs Codex-Estimated divergence).
6. **`test_codex_pricing_fn_edges`** — the pure `codex_cost_estimate`: 0 tokens → 0.0; an **unknown/absent model → 0.0** (conservative, tokens still carried); large counts → no overflow; cost always ≥ 0. Asserts: the boundary + unknown-model fallback. Why: a fabricated cost is worse than a flagged 0.0 (the §11.4 fail-honest posture).
7. **`test_codex_usage_ledger_sums_deltas_utc_bucketed`** (`telemetry_pump.rs`/`projections.rs`) — append the delta `TelemetrySampled` events through the REAL write-actor (fake Clock, UTC-`Z`) → `proj_usage_ledger` has tokens/cost == cumulative (SUM-of-deltas) and `bucket_day` == the UTC date prefix.
