# /tdd brief — headless_vt_screen_model

## Feature
A daemon-internal headless VT model (`terminal/vt.rs`, wrapping `vt100::Parser`) that consumes a raw PTY byte stream and maintains an in-memory terminal **screen + scrollback** — the deterministic `bytes → screen-state` core the survival `Replayed` rung will serialize/replay (075b) and the read-pump will feed (075c). **Display-only — never a status source** (#9). No live PTY, no persistence, no contract change.

## Use case + traceability
- **Task ID:** P3.4-VT
- **Architecture sections it implements:** `ARCHITECTURE.md §6.4` (the Terminal Channel wire the VT model consumes — FROZEN 0.21.0), `§9` (terminal/ADR-009 — PTY is display-only), `§9.1` (harness adapter — status derives from structured streams, never PTY bytes), `§7.2` (harness-derived SoT — "never scrape PTY for machine state"), `§0.1` (O-2 session survival / accurate alt-screen VT re-render).
- **Related context:** the named 3.4 follow-on (the §6.4 AS-BUILT note already cites "the headless-VT/scrollback-fidelity follow-on consume this frozen contract"). `daemon/src/terminal/mod.rs` is the sibling (the `TerminalSession` read-pump + `FakePty` + the `next_terminal_action` watermark classifier; **LESSONS §24** — PTY display-only #9). The survival decision is `daemon/src/harness/resume.rs::decide_resume` (**LESSONS §36**) — its `has_scrollback`/`replayed_event_count` inputs are what 075c will feed from this model. Approach **A = `vt100` 0.16.2** is verified viable at authoring (see "Things to flag" Q1).

## Acceptance criteria (what "done" means)
- [ ] `HeadlessVt::new(rows, cols, scrollback_len)` builds a model with explicit dimensions (no magic default).
- [ ] `process(&[u8])` folds plain text into the screen: visible row content reflects the bytes written.
- [ ] `process(&[u8])` honors VT escape sequences: a cursor-move + overwrite sequence leaves the **final** cell state on screen (not the literal bytes).
- [ ] Scrollback accumulates: writing more lines than `rows` grows scrollback; `has_scrollback()` is `false` before any line scrolls off and `true` after; scrollback content is retrievable.
- [ ] Alt-screen tracked: `\e[?1049h` → `alternate_screen()` is `true`; `\e[?1049l` → `false`.
- [ ] `size()` reflects construction dims and a `resize(rows, cols)`.
- [ ] **#9 structural pin:** `terminal/vt.rs` exposes NO `status::Session` / `NormalizedStatus` / `derive_status` surface and imports nothing from `harness::*` status — a scoped grep test pins the model as display-only (the `terminal/mod.rs` #9 precedent).
- [ ] Untrusted/garbage/partial-escape input does not panic (tolerant parse).
- [ ] All unit tests in `daemon/tests/vt.rs` pass.
- [ ] `/preflight` clean (incl. `cargo audit` is a /phase-exit gate, not per-slice — the new `vt100` dep is flagged at Step 9).

## RED test outline (Step 2)
Tests to write in `daemon/tests/vt.rs`:

1. **`test_vt_plain_text_renders_to_screen`** — feed `b"hello"` → row 0 visible content is `hello`.
   - Asserts: `vt.screen_contents()` row 0 == `"hello"`.
   - Why: the `bytes → screen-state` core (§6.4 / §9 terminal display surface).
2. **`test_vt_csi_cursor_move_and_overwrite`** — feed `"abc"` then a CSI cursor-home + `"X"` → final row 0 is `Xbc`.
   - Asserts: escape sequences mutate cell state, not literal bytes rendered.
   - Why: the whole point of a VT emulator (§9 ADR-009).
3. **`test_vt_scrollback_accumulates`** — `new(2, 10, 100)`; write 5 newline-terminated lines → `has_scrollback()` true; scrollback holds the lines pushed above the 2-row screen.
   - Asserts: `has_scrollback()` false→true across the first scroll; scrollback length/content reflects the overflow.
   - Why: the `Replayed` rung keys off scrollback presence (`LESSONS §36` `decide_resume` `has_scrollback`/`replayed_event_count`).
4. **`test_vt_alternate_screen_toggle`** — feed `\e[?1049h` → `alternate_screen()` true; feed `\e[?1049l` → false.
   - Asserts: alt-screen state is tracked.
   - Why: O-2 "accurate alt-screen VT re-render" (§0.1).
5. **`test_vt_size_and_resize`** — `new(24, 80, _)` → `size()==(24,80)`; `resize(10, 40)` → `size()==(10,40)`.
   - Asserts: dimensions are explicit + mutable.
   - Why: dims are load-bearing for the 075b snapshot fidelity (§6.4 frames carry no dims — the model owns them).
6. **`test_vt_is_display_only_never_status`** (STRUCTURAL grep-pin) — assert `daemon/src/terminal/vt.rs` source contains no `derive_status` / `NormalizedStatus` / `status::Session` reference and no `harness::...status` import.
   - Asserts: the model is display-only; status is NEVER derived from the VT screen.
   - Why: **#9 never-scrape-PTY-for-machine-state** (§7.2 / §9.1; the `terminal/mod.rs` scoped grep-pin precedent, `LESSONS §24`).
7. **`test_vt_garbage_input_no_panic`** — feed invalid UTF-8 / a truncated escape (`\e[`) / random bytes → no panic; screen stays consistent.
   - Asserts: tolerant parse on untrusted ingress.
   - Why: untrusted-input-parsed-tolerantly (the `LESSONS §42` parser family).

## Things to flag at Step 2.5
1. **`vt100` API meets the requirement?** Verified at authoring (vt100 0.16.2): `Parser::new(rows,cols,scrollback_len)` + `process(&[u8])` + `screen()`; `Screen::alternate_screen()`, `set_scrollback`/`scrollback`, `contents()`/`contents_formatted()`/`state_formatted()`, `contents_diff`. The visible+alt-screen state round-trips cleanly via `state_formatted()` (that's 075b's serialize). The one gap — no single-call scrollback-history serializer — is irrelevant here (075a is just the model) and resolved in 075b by byte-stream-as-serialization (the daemon owns the stream). My default: **proceed with A (`vt100`).** If you hit a concrete API blocker that `vt100` can't express cleanly, STOP and flag — B (`vte`+custom) is the sanctioned fallback (re-surface to the orchestrator → lead, NOT C).
2. **Module location + type name.** My default: `daemon/src/terminal/vt.rs`, type **`HeadlessVt`** (keeps the VT model adjacent to `TerminalSession` for the 075c read-pump tap). Alt: a `vt/` submodule. Vote: `terminal/vt.rs` + `HeadlessVt`.
3. **`scrollback_len` (the vt100 ring capacity) — fixed const or ctor arg?** My default: a **ctor arg** with a module-const default (e.g. `DEFAULT_SCROLLBACK_ROWS = 10_000`) — deterministic + bounded memory; the config/policy surface is a later concern. Vote: ctor arg + const default.
4. **Scrollback accessor shape for 075b/c.** This slice only needs `has_scrollback()` + a way to read scrollback for the test. My default: expose `has_scrollback() -> bool` + `scrollback_len() -> usize` now; defer the full serialize accessor to 075b. Vote: minimal accessors now.
