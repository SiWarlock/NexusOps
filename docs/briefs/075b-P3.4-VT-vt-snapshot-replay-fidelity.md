# /tdd brief — vt_snapshot_replay_fidelity

## Feature
Add **serialize → restore** to `HeadlessVt` (075a): a `snapshot()` that captures the screen + scrollback (formatting preserved) and a `restore()` that rebuilds an equivalent `HeadlessVt` from it — proven by a **golden-corpus replay-fidelity harness** (recorded byte streams → snapshot → restore → equivalent re-render, incl. alt-screen). This is the `Replayed`-rung "accurate alt-screen VT re-render" mechanism (O-2). Daemon-internal; in-memory only (no persistence — that's 075d); NO contract.

## Acceptance criteria (what "done" means)
- [ ] `HeadlessVt::snapshot() -> VtSnapshot` captures dims + scrollback_capacity + the screen + the scrollback (a daemon-internal type; NOT a `shared/` contract).
- [ ] `HeadlessVt::restore(&VtSnapshot) -> HeadlessVt` (or `from_snapshot`) rebuilds an equivalent model.
- [ ] **Visible-screen fidelity:** restore of a plain + an escape-heavy (color/cursor/attrs) stream yields identical `screen_contents()`.
- [ ] **Scrollback fidelity:** a stream that overflows the screen round-trips — restored `scrollback_len()` equals the original and `view_at_scrollback(k)` matches for every `k` in range.
- [ ] **Alt-screen fidelity:** a snapshot taken while alt-screen is active restores with `alternate_screen()==true` and the alt content intact; a snapshot taken after `?1049l` restores the normal screen + its preserved scrollback.
- [ ] **Idempotent round-trip (the loss-proof):** `snapshot(restore(s)) == s` (byte-identical) — serialize loses no information.
- [ ] `resize()` after restore behaves identically to resize on the original.
- [ ] All unit tests in `daemon/tests/vt.rs` (extends the 075a file) pass.
- [ ] `/preflight` clean.

## RED test outline (Step 2)
Tests to write in `daemon/tests/vt.rs`:

1. **`test_vt_snapshot_restore_plain_text`** — feed plain text → snapshot → restore → `screen_contents()` identical.
   - Asserts: visible content survives round-trip. Why: the serialize/restore core (§6.4/§9).
2. **`test_vt_snapshot_restore_escape_heavy`** — feed color/cursor/attr escapes → round-trip preserves the rendered screen (compare via the idempotent-snapshot check + `screen_contents()`).
   - Asserts: formatting (not just text) survives. Why: O-2 "accurate … VT re-render" (§0.1).
3. **`test_vt_snapshot_restore_scrollback`** — overflow the screen → restored `scrollback_len()` == original AND `view_at_scrollback(k)` matches ∀k.
   - Asserts: scrollback history survives. Why: the `Replayed` rung carries scrollback (LESSONS §57 / §36).
4. **`test_vt_snapshot_alt_screen_active`** — enter alt-screen (`?1049h`) then snapshot → restore has `alternate_screen()==true` + alt content intact.
   - Asserts: alt-screen-active snapshots round-trip. Why: O-2 alt-screen fidelity (the §0.1 must-have; the trickiest case — two buffers).
5. **`test_vt_snapshot_alt_screen_exited_preserves_scrollback`** — alt-screen on→off (`?1049l`) then snapshot → restore shows the normal screen + its preserved scrollback (the alt-grid-clobber regression's serialize cousin).
   - Asserts: leaving alt-screen restores the normal buffer + scrollback. Why: LESSONS §57 alt-grid edge through serialize.
6. **`test_vt_snapshot_idempotent`** — `snapshot(restore(s)) == s` byte-identical across the corpus.
   - Asserts: zero information loss. Why: the strongest fidelity pin without a private cell API.
7. **`test_vt_resize_after_restore`** — restore then `resize()` == resize on the original.
   - Asserts: restored model is fully live, not a frozen husk. Why: the model is reused post-restore (075c).

## Things to flag at Step 2.5
1. **Snapshot strategy.** (a) serialize the CURRENT vt100 state — `state_formatted()` for the visible screen (round-trips alt-screen/cursor/attrs) + the formatted scrollback rows (oldest→newest), restore = `process()` the captured bytes into a fresh `Parser`; (b) retain the raw byte stream + re-feed (perfect determinism but the model must hoard bytes — unbounded/memory); (c) hybrid. My default: **(a)** — self-contained, no raw-byte hoarding, leans on vt100's documented `state_formatted` round-trip. If the alt-screen-active case (two buffers) can't be reconstructed cleanly via (a), flag it — that's the one place (b) might be needed for a sub-part. Vote: **(a)**.
2. **`VtSnapshot` shape.** A typed daemon-internal struct `VtSnapshot { rows, cols, scrollback_capacity, screen: Vec<u8>, scrollback: Vec<Vec<u8>> }` (or a versioned flat blob). My default: the **typed struct** (clearer; 075d serializes it to the sidecar; add a `version: u8` header field so 075d's persisted format is migratable). Vote: typed struct + a version byte.
3. **Golden corpus source.** Synthesized committed byte-stream fixtures (hand-authored escape sequences; deterministic) vs a captured real PTY sample. My default: **synthesized committed fixtures** (deterministic, no live capture — the recorded-fixture discipline; matches 075a). Vote: synthesized.
4. **Restore API form.** `HeadlessVt::restore(&VtSnapshot) -> Self` vs a free `fn restore(snap) -> HeadlessVt` vs `From<&VtSnapshot>`. My default: an **associated `from_snapshot(&VtSnapshot) -> Self`** (mirrors `new`). Vote: `from_snapshot`.
