# /tdd brief — durable_redacted_scrollback_store

## Feature
The durable §15-gated `ScrollbackStore` implementation behind the 075c seam: persist each session's VT scrollback snapshot to a **0600 sidecar file**, with the **§15 Redactor run over the plain text BEFORE write** (USER ruling ① = A: persisted form is **redacted plain-text**, formatting dropped; the live/in-memory re-render stays formatted). Swapping it in for the 075c no-op placeholder makes the **`Replayed`-after-daemon-restart** rung live. 🔴 **Invariant-touching (§15): the sidecar may NEVER hold an unredacted secret — the redaction-before-persist invariant binds it exactly as it binds the event store (forbidden #3).**

> **Widens phase scope because** this slice implements the §15 redaction-before-persist invariant + the §8/§17 survival store (the VT arc's safety tail), while the model/serialize/wiring stayed Phase-3 terminal (075a–c).

## Acceptance criteria (what "done" means)
- [ ] A `FileScrollbackStore` (in `runtime/` or a new `scrollback/` module — wherever it can hold the Redactor + do FS without breaking the `session/` cat-1 boundary) implements the 075c `ScrollbackStore` trait.
- [ ] **`save`:** derives the **plain text** from the `VtSnapshot` (`from_snapshot` → `screen_contents()` + scrollback rows), runs the **§15 Redactor** over it, and writes a **redacted-plain-text** sidecar. The only serializable on-disk type holds **post-redaction** text (so an unredacted secret structurally cannot reach the file — the §16 co-located-gate shape).
- [ ] **🔴 §15 redaction-before-persist:** a snapshot whose text contains a secret → the sidecar file on disk NEVER contains the raw secret (it's masked). Mirrors the event-store redaction pin.
- [ ] **Fail-closed:** if redaction cannot complete, the sidecar is NOT written (the scrollback is lost → `Relaunched`, which is safe) — never persist unredacted.
- [ ] **Perms:** sidecar dir is **0700**, files **0600** (created fail-closed — a perms-set failure aborts the write, the §15 #11 pattern).
- [ ] **`load`:** reads the sidecar → reconstructs a (plain-text) `VtSnapshot`; absent/corrupt/partial → `None` (fail-safe, no panic).
- [ ] **Retention:** `evict(session_id)` on terminal reap; a **startup orphan-sweep** (sidecars with no matching `proj_session`); a **size/age backstop**.
- [ ] **Production wiring:** `main.rs` builds the real `FileScrollbackStore` and injects it (replacing the 075c no-op placeholder) into the producer + recovery → the `Replayed`-after-restart path is live; the `session/` cat-1 import-grep still passes.
- [ ] All tests pass; `/preflight` clean; `cargo audit` (the new dep, if any — likely none) at /phase-exit.

## Wiring / entry point (Step 7.5)
`main.rs` constructs the real `FileScrollbackStore` (data-dir, Redactor) and injects it as the `Arc<dyn ScrollbackStore>` into `spawn_supervisor_task`/recovery (the 075c seam — swapping the no-op placeholder). **This is the slice that makes `Replayed`-after-daemon-restart REACHABLE in production** (075a–c built the mechanism; this lands the durable store). Eviction is reachable from the terminal-reap path + a startup sweep. /wired the save (SessionActor tick/reap → store) + the load (`run_restart_recovery` → store) + the evict (reap + startup).

## RED test outline (Step 2)
1. **`test_durable_round_trip`** — `save` a snapshot with known plain text → `load` → a `VtSnapshot` whose `screen_contents()` matches (plain-text). Why: the store contract.
2. **`test_redaction_before_persist`** 🔴 — a snapshot whose text holds a secret (e.g. an `sk-…`/high-entropy token) → read the sidecar file bytes → the raw secret is ABSENT (masked). Why: §15 secrets-never-at-rest (the event-store redaction pin, forbidden #3).
3. **`test_redaction_failure_fail_closed`** 🔴 — inject a failing/again-asserting redactor → `save` writes NO sidecar (`load`→`None`); never an unredacted file. Why: §15 fail-closed (the #3 / §16 posture).
4. **`test_sidecar_perms_0700_0600`** — the dir is 0700, the file 0600. Why: §15 #11 (the Codex-rollout precedent).
5. **`test_load_absent_or_corrupt_is_none`** — `load(unknown)`→`None`; a truncated/garbage sidecar → `None` (no panic). Why: fail-safe recovery read.
6. **`test_evict_removes_sidecar`** — `evict(sid)` → file gone, `load`→`None`. Why: retention (③).
7. **`test_startup_orphan_sweep`** — a sidecar with no matching `proj_session` is removed at startup; a live session's is kept. Why: retention (③).
8. **`test_size_age_backstop`** — an over-cap/over-age sidecar is evicted by the backstop. Why: retention bound (③).
9. **`test_recovery_end_to_end_replays`** — save via the real store → `run_restart_recovery` loads it → `decide_resume`→**`Replayed`** (the 075c FakeStore path, now on the real store). Why: the live survival path (§8/§17).

## Things to flag at Step 2.5
1. **Plain-text extraction from `VtSnapshot`.** The store needs the snapshot's plain text to redact. My default: `from_snapshot(snap)` → `screen_contents()` + per-row `view_at_scrollback()` (reuses 075b's restore; no `VtSnapshot` change). Alternative: have the producer pass plain text alongside (a 075c change — avoid). Vote: restore-then-extract.
2. **On-disk format + the no-unredacted-type guarantee.** A `PersistedScrollback { version, rows, cols, screen_text: String, scrollback_rows: Vec<String> }` where the `String`s are POST-redaction — the ONLY `Serialize` type, so an unredacted value structurally can't be written (the §16 co-located-gate). serde_json (codebase-consistent, inspectable) vs a compact binary. My default: **serde_json + the post-redaction-only struct**. Vote: json + structural-guarantee.
3. **`FileScrollbackStore` home (cat-1).** It holds the Redactor + does FS → it lives in `runtime/` (or a new `scrollback/`), NOT `terminal/`/`session/`. The 075c trait stays in `terminal/`; `session/` holds only the `Arc<dyn ScrollbackStore>` (cat-1 intact). My default: a new `daemon/src/scrollback/` module (or `runtime/`). Vote: `scrollback/` module, injected.
4. **Atomic write + single-writer-per-sidecar.** Each session's actor writes its OWN sidecar (keyed by `session_id`) → no cross-session contention; tick-save + reap-save are serialized within the one actor. My default: **write-temp-then-rename** (a crash mid-write can't corrupt an existing sidecar; a partial temp → `load` ignores it). The single-writer-#3 rule is about `nexusops.db`, not per-session sidecar files (confirm). Vote: atomic temp+rename, per-session keying.
5. **Backstop thresholds (③).** Size cap per sidecar + total dir cap + max age. My default: a per-sidecar cap aligned to `SCROLLBACK_CAPACITY` × a row-size bound + a conservative dir cap + an age TTL (e.g. 7d). Vote: sensible bounds (name them in the brief's follow-up; tune later).
