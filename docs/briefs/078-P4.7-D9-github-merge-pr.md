# /tdd brief — github_merge_pr

## Feature
`github.merge_pr` — a **🔴 cat-1, risk-3, NON-standing-grantable** Gateway mutation that merges a remote PR (head→base) via octocrab `pulls().merge()`, SHA-pinned to the approved PR head, emitting a `PullRequestMerged` audit event and folding the PR's projection to terminal `Merged`. The FIRST GitHub *write* beyond `create_pr`; mirrors the `github.create_pr` executor precedent plus the merge-specific safety knobs the user steered (2026-06-20).

## Things to flag at Step 2.5
1. **`sha` required or optional?** My vote: **REQUIRED** — the user-approved anti-race guard only works if the human approves a specific head SHA (octocrab 409s if head moved). Companion flag: `proj_pull_request`/`PullRequestRow` carry NO `head_sha` today, so the live UI Merge button needs `head_sha` exposed (a follow-on enrichment, gated on the PR-status-refresh sync) — **do not silently drop**; record as a Step-9 carry-forward. The mechanism is fake-tested now regardless.
2. **`merge_method` required or default-to-merge?** My vote: **REQUIRED** — audit-integrity: the approved+audited Action must name the exact method that executes (the prototype's Merge button picks one). No silent server-side default.
3. **resource_ref + idempotency formula.** My vote: a **Repo `resource_ref`** (the audit/policy identity, mirroring `github.sync_reviews`) + **`IdempotencyFormula::FromInputs`** (the key = hash of raw inputs incl. `pr_number`+`sha` → uniquely identifies THIS merge → LESSON 21 executing→keep-key double-run protection). Alternative: a PR-fine-grained `NaturalResourceRef` if a PR `ResourceType` is cleaner. Confirm the exact `ResourceType` for the ref.
4. **Commit count.** My vote: **2** — (1) the contract freeze (catalog entry + `PullRequestMerged` + CONTRACT bump + §2.5-seam snapshots), (2) the cat-1 mutation vertical (policy gate + write-client + executor + fold + nudge). The safety-pin-own-commit rule (root CLAUDE.md / LESSON 43) — confirm whether the policy requester-gate wants its own commit.
5. **Fold now vs audit-only?** My vote: **fold now** — a row-mutating event with no projector arm + nudge is a silent stale-UI bug (LESSON 51); the fold is deterministic + synthetic-event testable now (the D5b-1 fixture-fed precedent), independent of the auth-gated live merge.
