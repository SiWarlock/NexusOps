## Things to flag at Step 2.5
1. **The canonical register-mutator at cold-start — how to write {row + event} atomically.** The seed runs in `bootstrap.rs` pre-runtime via `EventStore` directly (no Gateway/write-actor yet). My default vote: **extend the store with one txn that appends `ExecutionProfileRegistered` AND INSERTs the canonical row, §15-redacting the row payload before INSERT** (the LESSON-16 dual-gate applied at the store level — the cleanly-established mutator pattern the lead asked for). Don't write the row and event in two separate steps (crash-between → divergence).
2. **Default-profile shape.** What does the seeded default carry? My default vote: **`provider=anthropic`, `harness=claude_code`, `model=NULL`, `account_alias=NULL`, `keychain_ref=NULL`, `status='available'`** — a usable default whose SECRET/account binding lands in 5.3b (5.3a is non-secret). Confirm the provider/harness defaults (claude-first matches the MVP cat-4 = PTY-primary Claude).
3. **How `resolve_profile` reads the registry.** It runs at execute-time on the write-actor. My default vote: **an injected read seam** (a `ProfileStore`/`ProfileLookup` trait the `SessionExecutor` holds, mirroring the `launcher`/`supervisor` seams) so resolution is deterministically unit-testable; production reads the canonical table over a read-only WAL conn. Avoid hard-wiring a raw connection into the executor.
4. **Fail-closed error surface for an unknown id.** My default vote: a typed `ProfileNotFound` → `ExecutionOutcome::Failed` with a **structural** reason (no raw id echo beyond the requested-id string the requester already supplied); resolve becomes `Result<ExecutionProfileId, _>`; `execute_create` maps Err → Failed BEFORE launching (no orphaned session-actor on a profile failure).
5. **Commit count.** My default vote: **2** — **C1** the contract freeze (`ExecutionProfileRegistered` + CONTRACT 0.43.0 + schema-snapshot + 3-way verify), **C2** the durable-registry vertical (MIGRATION_16 + `profiles/` + seed + resolve-fallible). The freeze is atomic (the schema-diff test-9 would red mid-split — the D9/D10 C1/C2 precedent). NON-cat-1, so no separable safety-pin-own-commit.
