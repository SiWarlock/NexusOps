# /tdd brief — pull_request_head_sha

## Feature
Expose **`head_sha`** (the PR's current head commit SHA) on `PullRequestRow`, folded from the **authoritative GitHub PR sync** through `proj_pull_request` — the anti-race SHA-pin **source the UI reads** to pin a cat-1 merge/review (D9/D10) to the exact reviewed commit. Additive, read-only, CONTRACT-additive (the D6 diff-stats LOCKSTEP precedent).

## Safety framing (load-bearing — security-reviewer `invariant`, the §6.x SHA-pin axis)
The field itself is NON-cat-1 additive, but it is load-bearing for a cat-1 mechanism. **Two properties are pinned (both verified to hold pre-authoring — no Finding):**
- **(a) Authoritative, unspoofable source.** `head_sha` is captured ONLY from `pr.head.sha` on the octocrab PR object inside `extract_pr_signals` (the daemon-synced GitHub GET) → `PullRequestSignals` → `PullRequestSynced` → `proj_pull_request`. It is **NEVER** read from `req.inputs` / UI / any proposer. Pinned by a producer-source test + the absence of any inbound write path.
- **(b) The daemon's anti-race stays the LIVE check, not this field.** D9 `github.merge_pr` passes the **requester-supplied** `args.sha` (from `req.inputs`) to `handler.merge(pr).sha(args.sha)` → **GitHub 409s if the head moved** (`github_write.rs:304-308`); D10 same via `commit_id`. **This slice does NOT touch `github_write.rs`** — `head_sha` is the UI's display/pin-FORMATION source only; a stale projection value simply yields a fail-closed 409, never a wrong merge. Pinned by: the executors are untouched (the existing D9/D10 tests stay green).
