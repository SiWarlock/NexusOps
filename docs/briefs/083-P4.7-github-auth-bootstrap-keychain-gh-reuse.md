# /tdd brief — github_auth_bootstrap_keychain_gh_reuse

## Feature
The GitHub auth-bootstrap **foundation + the (Y) interim**: a shared **keychain-write primitive** (keyring) + the prod octocrab read/write clients **read their token from the OS keychain by the resolved account** + the **`gh auth token` reuse** acquisition (the daemon copies the user's existing `gh` login token into the keychain — no paste, no inbound-IPC secret) + a **per-connection live-writes-enabled toggle** (default OFF, flipped post-re-review). This lights up live authenticated GitHub Merge/Review — the last §4.7 go-live prerequisite. The in-app device-flow "Connect GitHub" UX = the fast-follow (brief **084**).

> **Decision LOCKED (lead→user gate satisfied):** GitHub App + device flow end-state; **rollout cut = (Y)** — gh-reuse interim NOW, device-flow fast-follow. Token-write = the DAEMON-sourced path (gh store / outbound OAuth poll — NOT inbound-secret-over-IPC). Live-enablement = the per-connection toggle post-re-review. Shared keychain-write primitive (5.3b reuses it). 🔴 mandatory security re-review IN-ARC, gating live-enablement.

> **⚠️ Device-flow token-lifetime fork (affects 084, NOT this brief) escalated separately:** GitHub's refresh-token grant REQUIRES `client_secret` (verified via Context7) → "expiring + silent refresh" is not serverless-safe (can't ship a client_secret in a desktop app). The fix (non-expiring user token) is a user decision pending for 084. **This interim (083) is unaffected — `gh` owns its own token refresh; the daemon only reads `gh auth token`.**

## Safety framing (cat-1 / secret-touching — security-reviewer `invariant`; the in-arc re-review gates live-enablement)
- **§15 #3 (no secret in events/payloads/rows/logs):** the gh token is read TRANSIENTLY (from `gh auth token`), written to the OS keychain, and **NEVER** written to an event, a DB row, an IPC response, or a log line. The audit event (`IntegrationTokenStored` or reuse the integration.connect registration) holds **ONLY the keychain_ref**. The token in daemon memory is zeroized after the keychain write.
- **§15 #4 (keychain-ref-only):** the DB / events carry only the `keychain_ref` POINTER; the secret lives solely in the OS keychain (keyring).
- **Confused-deputy (post-082):** the token is selected **per resolved account** — the github client for a write to repo X uses the keychain token for X's owner/account (resolved via the 082 audited-identity path), NEVER a single global token applied to any repo. Pin: a divergent-account token is not used.
- **Fail-closed:** keychain-unavailable / no token for the resolved account → the live write returns the existing typed `AuthFailed`/`Failed` (the current unauth-path behavior), never a silent fallback or an unauthenticated attempt presented as success.
- **The toggle gates live writes:** `live_writes_enabled` defaults **OFF**; only a post-re-review flip enables the resolved-token clients. With it OFF, the clients stay effectively unauth (writes fail-closed). **The mandatory security re-review must be CLEAR before the toggle may enable live writes** (the in-arc gate).
- **Unchanged supervision:** going live ≠ unsupervised — D9/D10's risk-3 + entry_no_standing_grant + per-action human approval still gate EVERY live write (the auth only makes an *already-approved* write reach GitHub).

- [ ] **gh-reuse acquisition:** a daemon path reads the user's `gh auth token` (transiently) → `store_secret` into the keychain under the per-account keychain_ref → registers/updates the integration_connection (keychain_ref pointer). Triggered by the UI "Connect via gh" (an IPC trigger — NOT a token-carrying IPC; the daemon sources the token itself).
- [ ] **gh-absent handling:** `gh` not installed / not authed → a typed, structural error surfaced to the UI (the "device-flow is the path for you" signal), never a panic / never a partial connection.
- [ ] **Clients read keychain token by resolved account:** the prod `OctocrabGithubReadClient` + `OctocrabGithubWriteClient` are built with the token resolved from the keychain by the **082-resolved account** (replacing `Octocrab::default()`); no token → fail-closed (unauth → 401 → the existing typed `AuthFailed`).
- [ ] **`live_writes_enabled` per-connection toggle** (durable; default OFF) — gates whether the authed write client is used for mutations; OFF → writes fail-closed. (A read may be allowed authed independently — Step-2.5 Q.)
- [ ] **Confused-deputy pin:** the token used for a write to a repo is the resolved account's token; a different-account token is not used (test).
- [ ] NO secret in any event / row / log (test: the audit event + the persisted rows carry only the keychain_ref; a token-shaped value never appears).
- [ ] `/preflight` clean; **security-reviewer `invariant` CLEAR; the in-arc mandatory re-review CLEAR before the toggle enables live writes** (the secret-write commit is gated on it).

## Wiring / entry point (Step 7.5)
`main.rs` builds the prod octocrab read+write clients with keychain-backed auth (token resolved per account) instead of `Octocrab::default()` (`:290`/`:435`). The gh-reuse acquisition is an IPC-triggered daemon path (UI "Connect via gh" → daemon reads `gh auth token` → keychain). The `live_writes_enabled` toggle (a durable flag) gates the write client. The github executors (082) already resolve owner/repo per account; token selection mirrors that resolution.
