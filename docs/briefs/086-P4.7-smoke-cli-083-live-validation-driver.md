# /tdd brief — smoke_cli_083_live_validation_driver

## Feature
Extend the `dev-client` smoke CLI with the subcommands that drive the 083 live-mutation chain end-to-end from the terminal — so the user can validate the live GitHub keychain-auth + the risk-3 merge/review path WITHOUT the UI (whose PR buttons are still disabled placeholders). Every subcommand is a THIN client that submits an EXISTING audited action through the EXISTING `submit_action`/approve pipeline — **no new mutation surface, no bypass.**

The methods/actions this wraps, ALL already on main: `connect_via_gh` (IPC method, 083 `b61cad4`); `integration.connect` (catalog, edges-029); `integration.set_live_writes` (catalog, 083); `github.create_pr` (catalog/executor, risk-3); `github.merge_pr` (catalog/executor, risk-3, D9 LESSON 60); `github.submit_review` (catalog/executor, risk-3, D10 LESSON 61). The LESSON 63/082 rule: merge/submit are PR-scoped and **fail-close NotFound on an out-of-band PR** → the chain MUST daemon-create the PR first (`create_pr` folds `proj_pull_request`), then act on it.

## Safety framing (touches the live merge/keychain path — security-reviewer `invariant`; NO new mutation surface)
- **No bypass (INV-SEC-1):** every subcommand submits an EXISTING `action_type` through the EXISTING `submit_action` method (or calls the EXISTING `connect_via_gh`); the daemon's policy gate + approval + executor + keychain write all run UNCHANGED. The CLI is just another local IPC client — it CANNOT bypass anything the pipeline gates (the daemon gates regardless of client). A risk-3 `merge_pr`/`submit_review` still requires a per-action approval (`smoke approve`), unchanged.
- **No new mutation surface:** zero new `action_type`s, zero new executors, zero new IPC methods, zero new keychain writes. The construction helpers only assemble inputs/resource_refs for actions that already exist. **(If implementation reveals it needs ANY new daemon-side surface beyond a thin client wrapper, STOP and flag at Step 2.5 — the lead pre-ruled this.)**
- **`dev-client`-gated:** all new subcommands live under the existing `#[cfg(feature = "dev-client")]` gate (the `create`/`kill` precedent) → OUT of the production `nexusopsd` binary. No production attack surface.
- **LESSON 63 confused-deputy preserved:** the merge/submit executors resolve owner/repo from the AUDITED `repo_id` resource_ref (082), never from a divergent input — the CLI supplies `repo_id` as the resource_ref; a wrong one fails-closed NotFound, never a cross-repo write.

## Acceptance criteria (what "done" means)
- [ ] **`connect-gh --provider github --account <acct>`** → calls the existing `connect_via_gh` IPC method → prints the returned `keychain_ref` (or the `gh_unavailable` status). No token printed.
- [ ] **`connect --provider github --keychain-ref <ref> --account <acct>`** → builds + submits an `integration.connect` `ActionRequest` (risk-2) via `submit_action` → prints the action/approval id (the user then `smoke approve`s it). Inputs = `{provider, keychain_ref POINTER, account}`, NO token (the LESSON 49 registration-only shape).
- [ ] **`set-live-writes --connection <connection_id> --enabled <true|false>`** → builds + submits `integration.set_live_writes` (risk-2) → prints the approval id.
- [ ] **`create-pr --project <project_id> --head <branch> --base <branch> --title <t> [--body <b>]`** → builds + submits `github.create_pr` (risk-3) with the `project_id` resource_ref → prints the approval id. (Seeds a daemon-folded `proj_pull_request` row so `merge-pr` can act — the LESSON 63 precondition.)
- [ ] **`merge-pr --repo <repo_id> --pr <n> --sha <head_sha> --method <merge|squash|rebase>`** → builds + submits `github.merge_pr` (risk-3) with the `repo_id` resource_ref + the SHA-pin → prints the approval id.
- [ ] **`submit-review --repo <repo_id> --pr <n> --sha <commit_id> --event <approve|request_changes|comment> [--body <b>]`** → builds + submits `github.submit_review` (risk-3) → prints the approval id. (The Review half of the "Merge/Review" centerpiece.)
- [ ] Each construction helper is a PURE `build_*_request(args) -> ActionRequest` fn (the `cmd_kill` pattern) — **unit-tested** for the right `action_type`, inputs, resource_refs, and (catalog-derived) risk; a wrong/missing required arg → a typed CLI error, never a malformed submit.
- [ ] The `USAGE` string + `daemon/src/smoke.rs` module doc list the new subcommands + the **end-to-end chain order** (connect-gh → connect → approve → set-live-writes → approve → create-pr → approve → merge-pr → approve).
- [ ] `/preflight` clean; security-reviewer `invariant` confirms NO new mutation surface + no-bypass + dev-client-gated.
