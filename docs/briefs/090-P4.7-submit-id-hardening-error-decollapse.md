# /tdd brief — submit_action_id_hardening_and_error_decollapse

## Feature
Two daemon-side fixes on the §6.1 submit / §6.4 error-surface path, both serving the cockpit Add-project blocker and honest smoke-testing:
1. **Submit hardening** — `submit_action` (+ `submit_action_plan`) fail-closed with `protocol_error` when `action_request_id` is empty or not a well-formed `ActionRequestId`, instead of silently accepting `""` (the id newtypes deserialize `#[serde(transparent)]` with NO parse-validation, and `request::insert` trusts the value → an empty-PK row → a confusing downstream `precondition_stale`).
2. **Error-map de-collapse** — `gateway_error_to_code` currently maps FIVE distinct `GatewayError`s → one `precondition_stale`, so the cockpit renders a "re-approvable stale card" for non-re-approvable faults (NotFound / AuditWriteFailed / IllegalTransition). Split them to honest, distinct existing `IpcErrorCode`s.

- **No new mutation/secret/IPC-method/migration surface** — a submit-path validation + an internal error-mapping refinement. security-reviewer runs (invariant policy); NOT full cat-1.

- **Convention candidate** — "the daemon validates client-supplied ids at the IPC boundary (parse-don't-trust) — `#[serde(transparent)]` newtypes do NOT validate on the wire, so an explicit `parse` guard is required at submit; a malformed id fails CLOSED with protocol_error, never a silently-accepted empty PK."
