# /tdd brief — project_friendly_name_on_rescan

## Feature
Give a registered project a human-readable NAME in the cockpit: add `name: Option<String>` (basename of the scan path) to the `ProjectRescanned` event, emit it from the `ProjectExecutor`, add a `name TEXT` column to `proj_project_activity`, and have the (091) `ProjectActivity` fold populate it. The UI consumes it the instant it's served (ui-082 already made `ProjectActivityRow.name` optional → zero UI rework). The friendly-name fast-follow to the 091 unblock (lead pre-ruled, autonomous mode).

## Things to flag at Step 2.5
1. **`name` Option vs required on the event.** My default vote: **`Option<String>`** — existing logged `ProjectRescanned` events have no name → required would break replay/`deny_unknown_fields`. Additive-optional is the safe pattern for an existing event type (the `head_sha`/`mergeable` precedent, LESSON 53).
2. **basename source = scan path vs repo_root.** My default vote: **scan path** (`req.inputs["path"]`) — the lead's ruling; always present (repo_root is None for non-git like the project-brain sidecar — the exact failing case). repo_root basename would leave non-git projects nameless.
3. **DO UPDATE name on re-rescan vs DO NOTHING.** My default vote: **DO UPDATE SET name** — a re-rescan (a new client-minted project_id → a new row anyway, but if the same id re-rescans) refreshes the name; harmless when unchanged.
