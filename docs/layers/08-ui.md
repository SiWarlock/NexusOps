# Desktop UI — projection-driven client (`ui/src/`)

## Executive summary

The desktop UI is the cockpit screen of NexusOps: a React 19 + Vite app (hosted in a Tauri 2.x shell) that shows what every agent session, pull request, approval, and project is doing right now. It is deliberately powerless — it reads projections (pre-computed read models) from the daemon and renders them; it never writes the database, never runs git, and never executes anything. Every value it shows is either a validated daemon payload or an explicitly-labeled fixture; every button that *would* change something is either wired or visibly disabled, never faked. Today the entire app runs against a `MockGatewayPort` serving contract-valid fixtures — the real Unix-socket transport (`UdsGatewayPort`) and the mutation/intent-submission seam are deliberately parked until the daemon freezes those contracts, so the UI's first mutation path is built exactly once against the real thing.

## Responsibilities

- **Accountable for:** rendering projections faithfully (status, attention, usage, audit, recovery, safety) with a glyph+label+severity channel for every signal — never color alone; failing closed at the boundary (a malformed payload throws, it is never rendered); explaining every degraded/read-only state to the human; and keeping all daemon access behind one `GatewayPort` seam (`ui/src/gateway-client/types.ts:35`).
- **Explicitly NOT:** the source of truth for anything. It holds no authoritative state (forbidden #2, `ui/CLAUDE.md`), never writes the DB (single mutator is the daemon), and its `canSubmitIntent` read-only gate is defense-in-depth only — INV-SEC-1 enforcement stays daemon-side (`ui/src/connection/read-only.ts:1-7`).
- **NOT yet:** a mutation client. There is no `submit_action`/`approve` on the port (named only in a comment, `ui/src/gateway-client/types.ts:4`) and no `UdsGatewayPort` implementation anywhere — every mention is a comment (`ui/src/gateway-client/mock.ts:9-10`, `ui/src/main.tsx:27`, `ui/src/connection/state.ts:2-3`).

## Interfaces & contracts

**Inbound (what the UI consumes):**

- `GatewayPort` — the §6.1 read surface mirrored UI-side: `get_projection<K>(name, scope?, page?) → Promise<ProjectionPageByName[K]>`, `subscribe(params) → AsyncIterable<ProjectionDelta>`, `get_capabilities() → {protocol_version, contract_version}`, plus transport-only members `getConnectionState` / `onConnectionChange` / `reconnect` (`ui/src/gateway-client/types.ts:35-50`). All daemon access flows through one implementation of this interface (forbidden #3).
- Six projections are loaded at shell start: `ProjectActivity`, `Session`, `PullRequest`, `ApprovalQueue`, `AuditTrail`, `UsageLedger` (`ui/src/shell/Shell.tsx:168-177`).
- Every payload is Zod-parsed at the boundary before view logic sees it; failure throws `BoundaryValidationError` and the Shell renders the load-error state (`ui/src/gateway-client/boundary.ts:52-71`, `ui/src/shell/Shell.tsx:205-212`).
- The handshake's `protocol_version` is checked against `SUPPORTED_PROTOCOL_RANGE {min:1, max:1}` → `compatible | update_required` (`ui/src/connection/version.ts:9-22`).

**Outbound (what the UI promises):**

- No mutations. The mutation-intent methods are absent by design; every mutation affordance (Gateway approve/deny, Pause, Approve-edit, conflict-resolve, integrity-acknowledge) renders **disabled** with an explanatory `title`, gated on `canSubmitIntent` where pre-threaded (`ui/src/overlays/GatewayModal.tsx:9-18`, `ui/src/safety/HardConflictCard.tsx:51-60`).
- `CONTRACT_VERSION` is re-exported from the generated layer and reported by the mock's `get_capabilities` (`ui/src/gateway-client/mock.ts:87-92`) — the version-gate sentinel test pins it to the frozen schema (`ui/src/contracts/generated.test.ts:55-59`).

## Data & state

- **Authoritative state: none.** All rendered entities come from validated projection rows; `ShellData` is a read cache assembled once per client (`ui/src/shell/Shell.tsx:75-84`).
- **Pure UI state (Lesson §13 family — no daemon dep, no intent gate):** view history stack+cursor (`ui/src/shell/view-history.ts:28-31`), active-project selection with stale-ID re-scoping (`ui/src/shell/active-project.ts:20`), selected session, the single open overlay (`ui/src/shell/Shell.tsx:66-73`), table sort/filter (`ui/src/views/sessions/SessionsTable.tsx:67-68`).
- **Shared item shape:** `ProjectionItem {id, label, machine, status}` — the single mapper source for sidebar/Command-Center/graph items; attention is never derived in mappers (`ui/src/projections/items.ts:24-29`).
- **Contracts:** generated Zod enums (13 value-sets, one flat object — `ui/src/contracts/generated.ts:8`) + provisional object shapes that delegate every enum field to the generated validators (`ui/src/contracts/provisional.ts:11-16`). Worktree's two axes collapse via explicit precedence (overlay-terminal > conflicts > pr_open > other-overlay > git) in `ui/src/status/worktree.ts:20-37`.
- **Fixtures:** projection fixtures under `ui/src/projections/fixtures/` (served through the boundary validator, `ui/src/gateway-client/mock.ts:39-46`); display-only side metadata (repo slugs, branches, harness chips) in `ui/src/shell/display-meta.ts`; recovery/safety fixtures default the Shell's props (`ui/src/shell/Shell.tsx:104-107`).
- **Tests:** 43 test files / 214 Vitest cases; currently 213 pass + 1 **intentional sentinel failure** (see Gotchas).

## Dependencies

- **Depends on:** `shared/contracts/schema/nexusops-contract.schema.json` — the frozen contract the Zod layer is generated from and drift-pinned to (`ui/scripts/gen-contracts.mjs:1-12`, `ui/src/contracts/generated.test.ts:8-20`); see [01-shared-contracts.md](01-shared-contracts.md). `NexusOps-ui-kit` — consumed as tokens-via-`styles.css` (imported first in `ui/src/main.tsx:6`) + component `.jsx` sources via the `@ui-kit` Vite alias with `resolve.dedupe(["react","react-dom"])` (`ui/vite.config.ts:12-27`) — never the prebuilt bundle. Conceptually, the daemon's projections ([04-projections.md](04-projections.md)) and IPC surface ([06-ipc.md](06-ipc.md)) — though today only via fixtures.
- **Used by:** the human. Nothing else calls into this layer; `main.tsx:30-34` mounts `<Shell/>` as the production entry point. The Tauri Rust host (`ui/src-tauri/`) stays logic-free per `ui/CLAUDE.md`.

## How it works (flow)

```
main.tsx (kit tokens → 3 theme layers → focus.css → <Shell/>)
   │
Shell ── new MockGatewayPort()                 (Shell.tsx:114 — UdsGatewayPort pending)
   │        │
   │   get_projection ×6 + get_capabilities    (Shell.tsx:168-177)
   │        │
   │   parseProjectionPage (Zod, fail-closed)  (boundary.ts:52-71; mock routes
   │        │                                   fixtures through it, mock.ts:65-74)
   │   checkVersionCompat → version state      (Shell.tsx:185; version.ts:16-22)
   │
   ├─ ReadOnlyProvider{connection,version} → canSubmitIntent (fail-safe FALSE)
   ├─ TopBar (back/forward ← useViewHistory; ProjectSwitcher; overlay triggers)
   ├─ banner stack: DegradedBanner · RecoveryBanner · AuditIntegrityAlert ·
   │                HardConflictCard            (Shell.tsx:320-335 — 3 distinct concerns)
   ├─ Sidebar (tree + nav) → navigate(view) / openSession
   ├─ main: 12-way view router                  (Shell.tsx:349-417)
   │     CommandCenter ← groupForCommandCenter ← describeStatus ← generated enums
   └─ EventDock (audit feed strip + ConnectionIndicator)
```

1. **Boot:** `main.tsx` imports kit tokens, then `theme/global.css` → `shell.css` → `components.css` → `a11y/focus.css` in load-bearing order (`ui/src/main.tsx:6-21`), then mounts `Shell`.
2. **Load:** Shell builds one stable client (default `MockGatewayPort`, `Shell.tsx:114`), pulls all six projections + capabilities concurrently, derives switcher counts (`ui/src/shell/derive.ts:1-2`), and sets version compat. Until data lands it renders a loading state; a boundary rejection renders a `role="alert"` load-error (`Shell.tsx:205-220`).
3. **Render:** every status anywhere goes `(machine, status) → describeStatus → StatusPill/AttentionMarker`; Command Center buckets items via `triageBucket` (`ui/src/status/attention.ts:18-22`); rank ≥ 4 enters "needs my attention" (`:8`).
4. **Navigate:** all view switches funnel through `navigate()` (the single nav entry point, `view-history.ts:91`); TopBar Back/Forward move the cursor only; ⌘K/⌘⇧P/⌘⇧H toggle overlays (`Shell.tsx:144-162`).
5. **Degrade:** any connection/version change reflows through `deriveDegradedState`; the read-only gate flips fail-safe and every parked mutation control stays disabled; the banner explains *why* (`DegradedBanner.tsx:21-64`).

## Design decisions & rationale

- **Projection-driven re-attaching client** (ARCHITECTURE.md §11, §4.2): the UI renders state, it does not own it — so a UI crash/restart loses nothing and can never disagree with the audited event log. The alternative (UI-held optimistic state) was rejected as drift-prone (forbidden #2, `ui/CLAUDE.md`).
- **Decision C — park the mutation seam** (recorded in `IMPLEMENTATION_PLAN.md:58` and `docs/sessions/ui-002…md:50`): 6.3d's permission card is the UI's *first mutation path* (INV-SEC-1-adjacent), and a safety contract is the worst thing to build provisionally and reconcile. So `submit_action`/`approve`, the Terminal Channel, and 6.3d/6.3e are deferred until the daemon freezes those contracts — **build once against the real frozen contract**. The intent seam, when it lands, serves all consumers (permission card, per-hunk actions, Dispatch, Brain Run-via-Gateway, restart-session, policy grants).
- **Generated, drift-caught contracts** (§5.0): the Zod enum layer is machine-generated from the frozen schema, never hand-declared (Lesson §1), with accept-all/reject-unknown/set-equality/version tests (`generated.test.ts:23-59`). Provisional shapes are quarantined in one bannered file (Lesson §2).
- **Fail-safe read-only as defense-in-depth, not enforcement** (§11.4, §15): `canSubmitIntent` defaults FALSE and the daemon Gateway remains the real INV-SEC-1 guard (Lesson §4) — the UI gate only prevents *offering* a mutation that would be rejected anyway.
- **Single descriptor table for status policy** (§11.3/§11.1): one `(machine,status)` table feeds sidebar weight, queue membership, and sort, completeness-pinned to the generated enums so a daemon-added status fails CI rather than silently rendering idle (Lesson §5; `descriptors.test.ts:22-38`).
- **Never color alone + a11y as merge gate** (§11.6): four-channel status (color+glyph+label+motion), graph views ship with a table fallback, and the reachability audit is a vitest-free classifier that *throws* so a whole-Shell render sweep fails on the first keyboard-unreachable control (`reachability.ts:1-6`).
- **Wire-or-disable** (§11.6, Lesson §13): a named control is never a dead click — overlay triggers were disabled until their surfaces landed (`TopBar.tsx:110-117` doc), and all daemon-gated actions render disabled with honest titles.
- **Mock dogfoods the boundary** (§14): `MockGatewayPort` returns fixtures *through* `parseProjectionPage`, so the mock can never emit a payload the real boundary would reject (`mock.ts:1-10`, `:65-74`).

## Gotchas & sharp edges

- **DRIFT (live, intentional sentinel): `CONTRACT_VERSION` is `"0.12.0"`** (`ui/src/contracts/generated.ts:10`) **while the frozen shared schema is `x-contract-version "0.14.0"`** (`shared/contracts/schema/nexusops-contract.schema.json:1064`). The drift test `generated_contract_version_matches_frozen_schema` (`ui/src/contracts/generated.test.ts:55-59`) **currently FAILS** — verified by running the suite: 213/214 pass, exactly this one fails. This is the drift-detection mechanism firing as designed after the daemon bumped the schema; the fix is regenerating via `ui/scripts/gen-contracts.mjs` (`pnpm gen:contracts`) and re-checking the enum diffs.
- **DRIFT (stale doc comment):** `ui/src/views/sessions/SessionsTable.tsx:64` says "Board / **filtering** / model+team columns are deferred" — but filtering is implemented right below it (filter state `:68`, build→filter→sort pipeline `:73-77`, status/search controls `:89-115`). The comment predates the filtering slice (`IMPLEMENTATION_PLAN.md:38` records it landing in `9a7945f`).
- **`UdsGatewayPort` does not exist** — it appears only in comments (`mock.ts:9-10`, `types.ts:5`, `main.tsx:27`, `state.ts:3`). The app's production entry point instantiates the mock (`Shell.tsx:114`). Known carry-forward gated on daemon Phase 1.5, not an oversight — but anyone reading "real client" into those comments will be misled.
- **`SUPPORTED_PROTOCOL_RANGE` is UI-pinned, not architecture-pinned:** §6.4/§16 say the handshake carries `protocol_version` but fix no numeric range, so the UI hardcodes `{min:1,max:1}` with an explicit flag comment (`ui/src/connection/version.ts:6-9`).
- **The "checking" banner is wired but trigger-pending:** with the mock, version resolves in the same `Promise.all` as data, so the connected-but-version-unknown window never actually displays until the real reconnect/re-handshake exists (`Shell.tsx:228-233`).
- **Unknown status is loud, not silent:** `describeStatus` returns rank 3 + `visualKind:"unknown"` for any uncovered pair (`descriptors.ts:169-187`), and `StatusPill` maps non-kit kinds to the kit's `degraded` pill rather than the kit's own silent `||idle` fallback (`StatusPill.tsx:17-21`). Both guards are defensive — the completeness test makes them unreachable for frozen statuses.
- **Kit components have closed props:** `data-*`/aria must ride wrapper elements (`StatusPill.tsx:54-62`), the kit `GraphNode` needs a DOM-seam focusability patch (`ProjectGraph.tsx:84-122`), and a closed-prop control's accessible name is a visually-hidden child, never a wrapper `aria-label` (Lesson §6; `TopBar.tsx:27-64`).
- **Theme posture:** zero raw hex in all three theme CSS files (verified by grep) — but `TopBar.tsx:170` paints the decorative (aria-hidden) traffic-light dots with literal `#3b3b40`. The semantic-tokens-only rule is enforced on the CSS layers, not inline TSX chrome.
- **Repair aliases Retry today:** both call `client.reconnect()`; they are named separately so the divergence is explicit until the real §16 repair/update-relaunch flow lands (`Shell.tsx:246-251`).
- **`stale_precondition` is deliberately NOT a hard conflict:** the conflict card's `ConflictReason` enum is `["fencing_conflict"]` only — the re-approvable stale-precondition flow belongs with the future approval/preview surface (`ui/src/contracts/provisional.ts:47-56`).
- **Safety surfaces are Shell-level until Phase 8:** the hard-conflict card + integrity alert live in the banner stack; the full 7-group Human Input Queue host is deferred (`Shell.tsx:327-334`).
