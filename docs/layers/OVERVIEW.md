# NexusOps — System Overview

> Generated by `/layer-docs` (initial run, 2026-06-11, branch `planning/production-grade-migration`, base commit `9890cda`). Every claim is anchored to real code; drift between docs and code is flagged, not smoothed over.

## What it is

NexusOps is **air-traffic control for AI coding agents**: a macOS desktop control plane for dispatching, supervising, reviewing, and delivering the work of many Claude Code + Codex sessions across local projects. Its load-bearing idea is a single sentence (`ARCHITECTURE.md:6`): *a detached Rust daemon is the single, audited mutator of all state — every change is a typed, risk-classified, approved Action recorded as an immutable event; the UI reads projections; agents and the Project Brain only propose intents; the local machine is the trust boundary.*

## At a glance

- **Stack:** Rust (Tokio, rusqlite/WAL, schemars) daemon + `shared` contract crate · React 19 + Vite + Tauri 2.x + Zod UI · a sibling Python/FastMCP "Project Brain" (referenced, not built here)
- **Shape:** desktop platform, three local processes — daemon (trust core) · Tauri UI (reattaching client) · Brain sidecar (proposes only)
- **Entry points:** `daemon/src/main.rs:34` (`#[tokio::main]` — cold-start, write-actor, UDS listener) · `ui/src/main.tsx` (Vite/Tauri WebView) · `shared/src/bin/emit_schema.rs` (contract regeneration)
- **Build state (2026-06-11):** Phase 0 (spikes + contract freeze) and Phase 1 (trust-core spine) are **complete**; Phase 2 (Action Gateway) has only its security pre-task (2.0-SEC) done; UI Phase 6 is complete and paused. Tests: daemon 133 · shared 26 · ui 214 (213 passing — see drift flags).

## How it fits together

The one walkthrough to hang everything on — **what happens when an event is appended today** (the only mutation path that exists until the Gateway lands):

1. A caller (bootstrap registration `daemon/src/bootstrap.rs:165-166`, or a test) hands an `AppendIntent` to the **write-actor** — the single dedicated OS thread that owns the only writable DB connection (`daemon/src/runtime/writer.rs:153-157`; layer 07).
2. Inside one `BEGIN IMMEDIATE` transaction (`daemon/src/eventstore/mod.rs:234-242`; layer 02): the **redactor** masks the payload (layer 03) and the writer **fail-closes** if the result isn't `redacted` (`mod.rs:210-227`); the canonical `seq` is minted; the event row is inserted; every registered **projector** folds the event into its read model and offsets advance (`daemon/src/projections/mod.rs:80-130`; layer 04); **outbox** rows are written for external destinations (`daemon/src/eventstore/outbox.rs:61-85`).
3. After commit, the write-actor publishes a `ProjectionDelta` on the broadcast channel (`writer.rs`, publish-after-commit), which the **IPC subscribe push** (layer 06) forwards to any connected UI over the dedicated subscribe connection.
4. The **UI** (layer 08) renders projections it read via `get_projection` and updates from deltas — it holds no authoritative state. (Today it runs on `MockGatewayPort` + fixtures; the real UDS client is a known carry-forward.)
5. Around all of this, layer 07's loops keep the system live: the outbox drainer delivers external side effects with backoff (5s), the lease reaper frees expired leases (30s), and layer 05's fencing tokens stand ready to reject any stale holder's write.

Every value crossing a boundary above — status string, ID, envelope field, wire frame — is defined once in layer 01 and validated closed (reject-unknown) at each language boundary.

## Cross-cutting concerns

- **Safety invariants (root `CLAUDE.md` "Key safety rules" / `ARCHITECTURE.md §15`):** single mutator + INV-SEC-1 (no-bypass), redaction-before-persist, fail-closed-on-audit-write, fencing mandatory, `getpeereid` peer-auth, never-scrape-PTY. Each landed layer pins its invariants with tests (see each doc's Gotchas).
- **Determinism for testability (§12/§14):** all time and ID minting flow through injectable `Clock`/`IdGen` traits (`daemon/src/clock.rs:14-59`, `daemon/src/idgen.rs:12-62`) — golden-log replay tests are byte-identical.
- **Versioning:** two axes — `CONTRACT_VERSION` (schema artifact, `shared/src/lib.rs:32`, 0.14.0) vs `protocol_version` (wire handshake, `shared/src/ipc.rs:16-26`, {1,1}); plus DB `user_version` (6) with backup/rollback migrations.
- **Observability: largely absent by design-gap.** No structured-logging/metrics layer exists; status flows through events/projections and heartbeat staleness only. (A known production-posture gap — flagged in the planning digests, not invented here.)
- **CI: none.** No `.github/workflows/`; the schema-diff gate, 3-way contract verify, and all test tiers run locally only.

## Key decisions & trade-offs

The binding record is `ARCHITECTURE.md §0` (decision ledger) + `docs/planning/DECISIONS.md` (full ADRs). The ones that shape the code most:

- **Detached daemon from day one** (ADR-002) — agents must survive UI quit; forces the UDS seam and the reattaching-client UI.
- **SQLite WAL, single writer** (ADR-003) — one write-actor thread owns all writes; measured headroom 12–19× at the N=20 design target (`ARCHITECTURE.md §18`).
- **Contract SoT = Rust authority → published JSON Schema → generated consumers** (§5.0 "Option A") — lets the UI track build in parallel against frozen contracts.
- **Live-lease fencing authority** ("Option B", human-ratified) — an expired holder is rejected *even if unsuperseded* (`daemon/src/locks/lease.rs:254-270`).
- **Quarantine + continue on corrupt rows** ("Option C", user-ruled) — the daemon starts, the gap is loud (`AuditIntegrityViolation`), the raw spine is untouched.
- **Mask-in-place over quarantine-divert** for redaction (LESSON §13) — a false mask loses a span; a false divert loses the whole event.
