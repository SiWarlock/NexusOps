## Decisions made

- **P5.3a Option B (durable registry) + both sub-decisions YES** (user-ruled): the canonical row is the source of truth (NOT event-sourced/projection); seed ONE default at cold-start via the audited System-actor mechanism; fail-closed on unknown profile id. `keychain_ref` is a §15 #4 POINTER only — the secret WRITE + startup self-test are 5.3b (separate commit).

- **082 create_pr resolves via the envelope `project_id`** (orchestrator-verified: create_pr's resource_ref id == the envelope project_id — the same singly-sourced audited value) because `proj_repository` is keyed by `project_id` and has no `repo_id` column (no PR row exists for a not-yet-created PR). merge/submit/sync use the D7 `(repo_id, pr_number)` PR-row path.
- **082 behavior change accepted as a STRENGTHENING:** merge/submit/sync now require a folded `proj_pull_request` row to resolve (an out-of-band-never-synced PR fail-closes NotFound); create_pr requires an envelope project_id + a proj_repository row. Fail-closed-by-default.
