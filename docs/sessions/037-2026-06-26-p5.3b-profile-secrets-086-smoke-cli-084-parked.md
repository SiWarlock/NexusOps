## Decisions made

- **085 ProfileSecretSet carries `{execution_profile_id}` ONLY** (not `{…, keychain_ref}`) — the ULID-bearing `nexusops/profile/<id>` pointer trips the §15 JSON-value redactor (masks it to `[REDACTED]`); the pointer is daemon-derivable, so the §15-correct shape carries the id + recomputes the pointer for the canonical-row UPDATE (the row keeps the full pointer via `apply_secret_set`'s bare-string redact). Orchestrator-ratified as §15-correct, not a regression.
- **085 `ExecutorKind::Profile`** (a new executor kind, not folded into `SessionExecutor`) — a profile-registry mutation is its own domain (the `ExecutorKind::Integration` precedent); `session.profile_change` stays in `SessionExecutor`.
- **085 canonical-row UPDATE rides the pipeline txn-B** atomic with the `ProfileSecretSet` append (forbidden #3 forces the write onto the write-actor; the SQL lives in `profiles::apply_secret_set`, the pipeline dispatches) — fail-closed (a fault rolls back both).
- **085 redacting `Debug` on `SetProfileSecretParams`** (a code-quality HIGH caught + fixed in-slice) — the inbound-secret wire type must never `{:?}`-echo the credential (the §43/§65 secret-Debug discipline; pinned by a contract test).
- **086 thin-wrapper, requester=User** — the CLI self-declares `requester_type=User`; that is the PRE-EXISTING `submit_action` trust model (getpeereid uid==daemon-uid IS the boundary; the `cmd_kill` precedent) — no new bypass.
- **086 `build_create_pr_request` parses `--project` at CLI time** (a code-quality MEDIUM fix) — a clear `--project: <parse error>` instead of a confusing daemon execute-time "missing the audited project_id".
- **084 L1 NON-EXPIRING, daemon-outbound-poll** (brief-LOCKED) — input-carried `{provider, account}`; the `auth_invalid_from_class` is a 401-class mapping, never a clock; the §17 `auth_expired` event variant + the §11.4 card are NAMED follow-ons (not landed).
