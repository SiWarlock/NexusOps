## Why this session existed

in R5 (the P7.1 Wave-D github/linear executors), then close the github read vertical (Wave-E). The
load-bearing risk: design-choice **3a** — the `ActionExecutor` trait is SYNC, so the async octocrab/

dedicated std::thread would panic.

## Decisions made
- **3a mechanism = captured `tokio::runtime::Handle` + `handle.block_on(timeout(fut))`** on the
  write-actor's dedicated std::thread (non-worker, no entered runtime → no panic), with a hard 30s
  `NETWORK_TIMEOUT` (the write-actor can never wedge). Structural grep-pin per executor (no
  `Handle::current()`/`spawn_blocking` in `execute()`).
- **`ExecutionOutcome::FailedWithEvents{detail,emitted_events}`** (edges-024 reuses it) — a daemon-internal
  gateway extension: a FAILED action emits structured observation events atomic with `ActionFailed`;
  `side_effect_applied()==false` → clean rollback on a txn-B fault. Additive (existing `Failed(String)`
  sites untouched).
- **Shared `classify_sync_failure → SyncFailure`** (Auth/TerminalNonAuth/Transient) — the §17 disposition
  in ONE exhaustive place; github + linear can't diverge. edges-024 refactored edges-023's
  `classify_failure` to call it (behavior-preserving — all edges-023 github tests stayed green).
- **Linear success emits NO domain event** (architecture-as-contract; the frozen 11-event family has
  `LinearSyncFailed` but no Linear success event — did NOT improvise a contract bump).
- **`pr_id` = `{repo_id}#{pr_number}` composite** (NOT a minted ULID — rebuild-safety).
- Auth bootstrap (octocrab handle / Linear OAuth-PKCE key) **deferred** — both clients take an injected
  handle; main.rs wires unauthenticated placeholders (a real call → 401→AuthFailed→Failed, fail-closed).

  write-actor up to `NETWORK_TIMEOUT`; bounded, but a future hardening moves slow external executors off
  the write-actor thread. `last-consumer-slice: a gateway execute-phase-offload hardening slice`.
